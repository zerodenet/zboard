## 范围与完成条件

保留现有自用面板闭环，小步修复测量中发现的问题。核心独占订单、权益、计量和授权状态；

SSH 测试服务器不能替代真实 Zero 数据面的撤权验证。已有本地改动不自动提交、部署或发布。

  RSS、容器内存和 CPU、数据库连接等待。应用和数据库都计入 1C1G 档案；负载生成器在容器外。
- 本地跨编译、宿主机资源、Docker 版本、数据库版本、Git HEAD 和工作区差异摘要必须进入结果。

- 24 小时从负载稳定并开始记录时计时；故障注入按时间点记录。环境重置或更换构建后重新计时。

### 2026-09-06：减少计量事务重复工作

[zero_flow_batch.go](../backend/internal/handler/zero_flow_batch.go) 新增仅在单个事务内存活的批处理状态：

- 同一凭据的归属、锁定订阅和端点只读取一次；保留的是必要的凭据标识，不保留密钥。
  多条流使用同一个已更新余额，因此共享额度耗尽时仍按剩余额度计费。
- 同一订阅的最终用量、状态和同一凭据的最后使用时间各写一次；账本与余额仍在原事务提交。
- SQLite 的重复报告查询每块最多 200 个 ID，账本插入每块最多 100 条。
  MySQL 保留由数据库比较报告 ID 并逐条写入账本，因为列排序规则可能把大小写不同的 ID
  视为同一报告；不能用 Go 字符串键代替该幂等语义。MySQL 同样复用锁定状态、合并余额及凭据更新。
- 批次结束或回滚后全部状态丢弃，不建立跨请求授权缓存，不引入插件、队列依赖或新的异步扣费窗口。

新增回归覆盖两份订阅余额隔离、批次间倍率变化、205 条事件跨块写入后的整体回滚和重放、
同批相同报告 ID/带空白报告 ID 重放。真实 MySQL 8.0.29 额外验证累计/乱序/耗尽和大小写等价
报告的幂等。后端全量测试、vet、计量相关 SQLite/MySQL 竞态检查均通过。

首轮同档案对比（32 条流/批、100 批、3 次、1C1G）已将 SQLite 的 SQL 从 292 次降至
75 次/批，约减少 74%；分配从约 2.75 MB 降至 1.24 MB/批，约减少 55%。
首轮计量吞吐实测 374–575 条事件/秒；最终构建复跑为 602–692 条事件/秒，
p95 为 65.8–88.9 ms/批，SQL 仍为 75 次/批，分配约 1.25 MB/批。
两次运行的速度有波动，不将其换算为固定的生产性能倍数。此为单订阅基准收益，
不代表混合 HTTP 负载、磁盘长期增长或真实节点撤权已达标。

最终证据目录：`.codex-local-artifacts/acceptance/accounting-20260906T082144Z-rxsX9u/`。
源码构建前后摘要一致；容器 1 CPU/1 GiB 约束已核验，退出码为 0，无 OOM，临时容器已清理。
下一阶段转入 10 节点、1,000 订阅、100,000 条历史记录与实际 HTTP 路由、事件缓冲消费者
一起运行的混合负载。该阶段尚未执行，24 小时长稳与真实节点撤权仍保持待验收。

### 2026-09-06：首屏聚合范围与分组索引

首屏查询新增一个最多读取 1,024 条最新原始记录的索引探测子查询。只有探测出的独立桶足够
覆盖当前页及下一页标记时，才将主聚合下界推进到探测中最早时间桶的起点；若桶数不足则
保持完整时间范围。下界与页面在同一条 SQL 的快照中计算，且始终保留完整时间桶，不截取
原始记录 ID。已有游标和 offset 分支保持原有范围规则，范围总数不受首屏下界影响。
