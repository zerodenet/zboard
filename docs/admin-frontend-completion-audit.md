# Zboard 管理端前端重构完成度审计

状态：目标仍在实施，不满足完成门槛。

审计日期：2026-07-24

## 1. 审计口径

本审计以当前工作树、`admin-frontend-system-redesign.md`、
`admin-frontend-implementation-plan.md`、路由、页面、公共组件、API handler、
OpenAPI 和测试为事实来源。构建成功、路由存在或已部署均不能单独证明完整目标完成。

## 2. 已有可靠证据

- 15 个有效管理端路由均已注册；`/admin/billing` 仅重定向到订单页。
- 主要管理列表已从任意长度卡片迁移为紧凑表格，并显示服务端总数与分页；Nodes、Protocols、
  Users、Orders、Subscriptions、Tasks、NodeGroups、Plans、Templates 和 Tickets 使用统一
  `useRemoteTable`，Traffic 记录、OperationLogs 和 AuditLogs 使用双向 `useCursorTable`。
- 两类远程表格都会区分首次加载和后台刷新、保留现有行、丢弃晚到响应并取消失效请求；offset
  表格额外修正越界页，cursor 表格直接消费服务端的“较新/较旧”游标；
  节点和协议列表聚合已移除逐行查询路径。
- 所有管理端与账户端表格都由共享 `DataTable` 承载，公开可访问 caption 与真实总行数，并统一内部
  横向滚动、固定主列/操作列和次要列视口优先级。Nodes/Protocols 进一步使用 `SortableHeader`、URL
  表格状态和跨页选择范围，排序方向具备 `aria-sort`，密度与选择范围均有明确契约。
- 状态标签统一包含语义图标和文本；数量列主要直接显示数字；管理列表时间主要使用
  `TimeBadge`。未知状态使用“未知状态（原值）”，无效时间保留原值在辅助说明中而不污染主显示。
- `FormField` 保留说明/错误槽位并生成 label、`aria-describedby`、
  `aria-invalid` 关联；有无备注的同类输入保持相同控制高度和说明/错误行高度。
- 金额、字节流量、倍率、端口、普通数字和日期使用领域组件：金额显示币种标准单位但保存整数分，
  流量显示 MiB/GiB 但保存字节，倍率显示 `×` 但保存 milli，端口固定 1–65535；页面不再直接声明
  原生 number/date 输入格式。
- 已建立表单 dirty 快照、统一放弃更改确认、字段错误 map 和首错聚焦；节点、协议、节点组、套餐、
  用户、任务、模板、工单、设置和初始化等主要表单已接入。10 个持久业务表单所有者还共用路由离开
  与浏览器刷新/关闭保护；只有对应编辑器打开且内容实际变化时才阻止离开。动态设置对 HTTP 409
  revision 冲突提供明确重载动作，不再把冲突降级成普通失败。
- 全部现有 `<form>` 已关闭浏览器原生校验气泡，并在发出请求前使用共享校验原语检查 UTF-8 字节、
  Unicode 字符数、邮箱、HTTP(S) URL、Slug、枚举及整数范围；错误进入相同 `FormField`、表单提醒和
  首错聚焦通道，字段修改后清除对应错误，服务端继续负责唯一性、模板执行和数据库状态等最终规则。
- 成功结果进入右上角 Toast；Toast 明确可关闭、相同活动消息去重且真实活动上限为 3 条。提交中的
  按钮显示 loading 并禁止重复提交；表单内失败就地显示，页面级或可行动错误保持显著可见，危险操作
  进入确认弹窗。
- 输出展示会清理 ANSI、控制字符、CRLF 和 Unicode 组合字符，并区分完整复制值与截断展示值。
  Axios 响应错误还会在进入任何页面前经过同一个边界：只接受长度受限的本地化消息、稳定错误码和
  合法字段名，移除替换字符并保留页面自己的可执行兜底；非对象原文、英文网关错误和无效错误码不会
  原样进入页面。SSH WebSocket 消息及任务托盘错误摘要也使用同一输出清理策略。
