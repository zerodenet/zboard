# zboard implementation roadmap

> 当前阶段：`v0.0.1` 内部工程基线。首个对外发布版本为 `v0.1.0`。

## 范围原则

- `v0.0.x` 只作为内部里程碑，不承诺公开兼容性。
- `v0.1.0` 只支持 Docker Compose / 单机容器化部署。
- Kubernetes 清单、控制 API、滚动升级和回滚自动化均不在当前路线范围内。
- 每个里程碑必须同时满足代码、测试、契约、迁移和操作文档的退出条件。

## 实现路径

| 里程碑 | 目标 | 主要交付 | 退出条件 |
| --- | --- | --- | --- |
| `v0.0.1` | 建立可重复验证的工程基线 | 统一版本号；锁定 Go/Node/pnpm；前端锁文件；后端单元测试；OpenAPI 校验；CI；Docker-only 范围收口 | 后端 test/vet/build、前端 typecheck/build、OpenAPI lint 全部通过 |
| `v0.0.2` | 收紧安全与信任边界 | 禁止默认生产管理员；强制安全 JWT 密钥；日志脱敏；SSH 凭据安全存储与主机密钥校验；节点上报鉴权、签名和幂等 | 默认配置无法带弱口令进入生产；敏感信息不落日志；伪造或重复流量上报被拒绝 |
| `v0.0.3` | 打通可信业务闭环 | 订单状态机与支付回调幂等；订阅生效/过期/流量耗尽；节点客户端配置交付；账单与流量对账 | 用户从下单到获取订阅、使用流量、额度扣减的端到端测试通过 |
| `v0.0.4` | 建立可运营能力 | 结构化日志、指标和审计；备份恢复；Docker 蓝绿切换与回退演练；故障诊断；端到端冒烟测试 | 可观测、可备份、可恢复、可回退，并保留演练证据 |
| `v0.1.0-alpha/rc` | 公开发布验证 | API/配置兼容性冻结；安全审计；安装和升级文档；发布候选镜像；真实环境验收 | 发布清单全部通过，无阻断级缺陷 |
| `v0.1.0` | 首个公开版本 | Git tag、镜像、校验信息、变更日志、支持与回退说明 | 发布产物可复现，Docker 部署和核心业务闭环验收通过 |

## 当前进度

### v0.0.1

- [x] 将仓库版本统一为 `v0.0.1`，明确 `v0.1.0` 为首个公开版本。
- [x] 固定 Go 1.26.5、Node.js 22.23.0、pnpm 11.9.0。
- [x] 增加 pnpm 锁文件、Vue 类型检查和可复现安装。
- [x] 增加后端关键辅助逻辑与版本元数据测试。
- [x] 建立后端、前端和 OpenAPI CI 门禁。
- [x] 移除 Kubernetes 资源、升级 API、前端入口和脚本。
- [x] 保留 Docker Compose、Docker 镜像和单二进制部署路径。

### 下一步：v0.0.2

1. 定义生产配置启动约束，移除默认管理员和默认 JWT 密钥。
2. 设计敏感字段存储方案，并完成 SSH 密码迁移与日志脱敏。
3. 为节点签发独立身份，流量上报增加签名、时间窗、nonce 和幂等键。
4. 增加负向安全测试与迁移回滚测试。
5. 完成安全退出条件后再进入 `v0.0.3`，避免在不可信数据上扩展计费闭环。
