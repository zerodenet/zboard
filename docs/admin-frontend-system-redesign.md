# Zboard 管理端前端系统重构草案

状态：产品方向已确认，已授权进入统一基础层与全页面实施。

更新时间：2026-07-22

## 1. 目标

本次工作不是逐页美化，也不是把其他页面复制成 `/admin/nodes` 的样子，而是建立一套覆盖全部管理端页面的产品与工程体系：

- 管理员能够在同一套信息架构中完成客户、商业、基础设施和系统运营工作；
- 页面在少量数据下保持清晰，在至少 1000 个节点、5000 个协议端点下仍可检索、比较、批量处理和恢复上下文；
- 输入、输出、状态、请求反馈和危险操作遵循统一契约；
- 公共组件真正拥有语义、尺寸、校验、可访问性和状态行为，页面不再自行拼装另一套规则；
- 列表与汇总接口采用分页、筛选、排序和批量聚合，不把全量数据或逐行查询压力转移给浏览器；
- 任何“已保存”“已发布”“已生效”都由对应事实证明，不用请求成功代替最终结果。

## 2. 范围和边界

### 2.1 本轮管理端范围

有效管理端页面共 15 个：

1. `/admin/dashboard`
2. `/admin/users`
3. `/admin/subscriptions`
4. `/admin/tickets`
5. `/admin/plans`
6. `/admin/subscription-templates`
7. `/admin/orders`
8. `/admin/nodes`
9. `/admin/protocols`
10. `/admin/node-groups`
11. `/admin/traffic`
12. `/admin/tasks`
13. `/admin/operation-logs`
14. `/admin/audit-logs`
15. `/admin/settings`

`/admin/billing` 当前只重定向到订单页，但 `frontend/src/views/Billing.vue` 仍保留一套已经失去有效路由的旧交易界面，应在迁移后删除，避免形成第二套业务与样式实现。

### 2.2 资源边界

重构必须保留 `docs/data-model.md` 中的资源所有权：

- Node 是独立 VPS 资产，拥有生命周期、SSH、Zero 连接、内核和计量凭证；
- ProtocolEndpoint 是绑定单一 Node 的可售网络资源，并唯一拥有流量倍率；
- NodeGroup 组织可售端点，Plan 只选择 NodeGroup；
- Order 保存商业快照，Subscription 保存已授予权益；
- 运行日志与安全/业务审计日志保持分离。

界面可以把相关事实放在同一个工作台中，但不能为了交互方便而重新混淆数据所有权。

## 3. 当前证据与限制

本草案基于当前工作树的路由、页面、组件、样式、API 客户端和 Go handler 审计。

- 15 个管理页面都自行组织工具栏、列表、表单、反馈和加载状态；不存在统一的数据工作台组件。
- `styles.css` 同时承担管理端、账户端、公开页和大量业务页面样式，设计令牌与业务 CSS 混在一个文件中。
- 已尝试在 Chrome 和应用内浏览器打开内网管理端；两个环境当前均停留在登录页，因此已认证页面的真实点击、ARIA、移动端溢出和长列表行为尚未完成浏览器补证。
- 当前工作树已有大量未提交改动。本文件是新增设计草案，不覆盖或整理其他人的现有改动。

## 4. 系统性问题清单

### 4.1 信息架构

- 页面按数据表分割，缺少面向运营任务的连续工作流。
- 对象详情、相关对象和运行事实通常通过跳转分散在不同页面，返回后筛选与选中状态无法恢复。
- 页面标题下普遍重复四个统计块，无论这些数字是否能帮助当前决策。
- 高频动作、低频配置和危险操作混在相同操作区，没有主次层级。
- 卡片、主从、表格、时间线和抽屉没有适用规则，选择主要由页面作者临时决定。

### 4.2 数据承载能力

- Nodes、ProtocolEndpoints、NodeGroups、Plans、Orders、Subscriptions、Users、TrafficRecords、TrafficReconciliation 和 SubscriptionTemplates 的管理接口当前没有完整分页响应。
- Tasks 接受 `limit/offset`，但只返回数组，没有 `total`，页面无法可靠表达范围。
- Tickets、AuditLogs、OperationLogs 和 ProtocolDeployments 已有分页雏形，但分页、筛选和 URL 同步仍由各页面重复实现。
- 多个页面为填充下拉框同时全量请求用户、节点、端点和套餐；数据越多，辅助选项本身就会成为主负载。
- 页面没有统一的取消请求、竞态保护、缓存失效、局部刷新和重试策略。
- 普通列表没有虚拟化或 DOM 上限；卡片页面会为全部数据创建高成本节点树。

### 4.3 后端查询契约

- `NodeListHandler` 全量查询并预加载内核状态。
- `ProtocolEndpointListHandler` 全量查询端点，并对每个端点分别执行在线流、有效凭证、最近使用、累计流量和今日流量 5 次查询。1000 个端点约产生 5001 次查询。
- `PlanListHandler` 在预加载 SKU 后又逐个套餐读取 NodeGroup，存在另一处按行查询。
- TrafficRecords 与 TrafficReconciliation 都可能读取全量记录或订阅后在内存/循环中组织结果。
- 当前 API 返回形式混合 `[]`、`{items,total,offset,limit}` 和单对象，没有统一分页元数据、排序描述、筛选回显或聚合区。

### 4.4 组件与样式

- `UiInput` 为所有非复选框输入移除了 `type` 和 `value`，破坏 password、email、url、number 语义以及只读值展示。
- `UiSelect` 从 `<option>` VNode 反向解析选项，无法自然承载远程搜索、分页选项、分组、模板、创建项和大数据选择。
- `UiButton` 依赖旧 `.button-*` class 推断 PrimeVue 属性，同时全局 CSS 仍保留旧按钮实现，形成双重样式来源。
- Settings 绕过 Ui 组件直接使用 PrimeVue，证明包装层还不能表达实际需求。
- `.field` 不保留提示/错误槽位高度，同一行有备注和无备注字段会发生高度与对齐差异。
- 原生控件、PrimeVue 控件和紧凑控件分别使用约 40、42、34 像素高度。
- 页面 scoped CSS 大量重复业务布局，无法靠修改令牌统一调整密度、状态和响应式行为。

### 4.5 表单

- 必填、选填、说明、单位、示例和危险影响没有统一字段结构。
- 创建与编辑使用不同原始单位，例如 GiB 与字节、元与分、倍率与千分值。
- 错误大量显示在表单顶部或全局 Toast，字段没有稳定的 `aria-invalid`、`aria-describedby` 和服务端错误映射。
- 无统一 dirty state、离开保护、保存前差异摘要、乐观并发冲突处理和保存后版本回显。
- 复杂表单在弹窗中无限增高；步骤、草稿和高级配置的适用边界不明确。

### 4.6 请求与反馈

- `TransientFeedback` 不渲染页面状态，只把成功和错误全部转成右上角 Toast。
- 页面首次加载失败、弹窗提交失败、行操作失败和高风险后台操作共享同一短时通道。
- Toast 固定在 4.2 或 6.5 秒后消失，无法承载重试、查看详情、复制错误或部分失败明细。
- 全局确认框只有一个槽位，第二个确认会直接取消第一个确认。
- 保存协议、创建任务和内核对齐等异步操作缺少统一的“请求已接受、执行中、部分成功、最终完成”状态模型。

### 4.7 输入输出

- 状态、协议名、时间、金额、流量、倍率、端口、布尔值和错误映射散落在页面函数中。
- 无效时间会回退原始字符串，后端错误和命令输出经常直接展示原文。
- 缺少统一时区、相对时间、精度、空值、异常值和复制原值规则。
- 原始 JSON、模板、命令输出和普通说明使用相同文本区域，缺少语法、行号、编码与敏感信息边界。

### 4.8 URL 与上下文恢复

- 少量页面只从 `route.query` 读取初始筛选，但筛选变化、分页、排序和当前对象不写回 URL。
- Nodes、Protocols、Plans、NodeGroups 和 Tickets 的当前对象或展开项刷新后丢失。
- 浏览器前进/后退无法恢复工作台状态，也无法分享精确问题上下文。

### 4.9 可访问性

- 依赖 `<label>` 包裹复杂布局，字段、按钮、提示和错误之间的语义关系不稳定。
- 表格缺少统一 caption、排序状态、选择说明和行操作命名。
- 抽屉/弹窗关闭后的焦点恢复、首错聚焦、Toast live region 和后台任务状态宣告尚未形成契约。
- 需要在真实浏览器中补充键盘顺序、焦点陷阱、ARIA 状态和移动端横向溢出验收。

## 5. 目标信息架构

主导航保持五个运营域，但页面内部按任务组织：

| 运营域 | 页面 | 主要任务 |
| --- | --- | --- |
| 工作台 | Dashboard | 异常分诊、待办、跨域跳转 |
| 客户与支持 | Users / Subscriptions / Tickets | 找到客户、理解权益、处理问题 |
| 商业管理 | Plans / Templates / Orders | 管理商品、交付格式与交易 |
| 基础设施 | Nodes / Protocols / NodeGroups / Traffic | 管理资产、可售服务、交付边界和计量 |
| 系统运营 | Tasks / OperationLogs / AuditLogs / Settings | 批量任务、运行故障、安全追踪和配置 |

跨页面对象链接统一携带稳定 ID 和 `return_to` 上下文；详情默认不通过新页面切断列表上下文。

## 6. 页面形态规则

### 6.1 卡片只用于

- Dashboard 的少量关键指标或异常摘要；
- 用户购买套餐等需要并列比较的选择；
- 单个对象的聚焦状态摘要；
- 空状态、危险说明或一次性结果。

卡片不得作为任意长度管理列表的默认容器，也不得在卡片内继续嵌套同等视觉权重的卡片。

### 6.2 表格用于

- 需要扫描、比较、排序、筛选、批量选择的同类对象；
- 用户、订阅、订单、节点、协议、节点组、套餐/SKU、任务和日志；
- 数据数量未知或可能增长的所有管理列表。

默认密度为 40px 行高，允许用户切换舒适密度，但字段结构和列宽不随页面自行改变。

### 6.3 主从与抽屉

- 桌面默认使用全宽数据表格，点击行打开路由驱动的右侧详情抽屉；
- 需要连续对话的 Tickets 可保留分栏，但列表必须分页、可搜索并具有独立滚动；
- Nodes 可以提供“固定详情”模式，把抽屉固定成分栏，默认仍保留完整表格扫描能力；
- 移动端详情使用全屏抽屉，不把双栏强行压成窄列。

## 7. 统一公共能力

### 7.1 页面与工作台

- `AdminPage`：标题、说明、主要动作、页面级告警和面包屑。
- `DataWorkbench`：筛选、列配置、数据表、批量栏、分页、空/错/加载状态和 URL 同步。
- `DataTable`：排序、选择、固定列、行菜单、键盘导航、骨架屏和密度。
- `FilterBar`：关键筛选常驻，高级筛选放入弹层；显示生效筛选标签和一键清除。
- `DetailDrawer`：对象标题、状态、标签页、操作菜单、返回焦点和 URL 状态。
- `BulkActionBar`：明确“当前页 N 条”或“全部筛选结果 N 条”，危险操作二次确认。

### 7.2 表单

- `FormField` 统一 label、required/optional、description、control、unit、hint、error 和字符计数。
- `UiInput` 必须显式支持 text/email/password/url/number/search/tel，不再删除原生语义。
- 金额、字节、倍率、日期时间、端口分别使用领域输入组件；浏览器显示人类单位，API adapter 负责转换。
- Select 接收结构化 `options`；大数据关系选择使用远程搜索 Autocomplete，不下载全部对象。
- 表单错误按字段映射；无法映射的业务错误显示在表单 Banner；页面 Toast 不承载提交失败。
- 表单具备 dirty state、关闭确认、保存中禁用、重复提交保护和冲突刷新。

### 7.3 反馈层级

| 层级 | 使用场景 | 是否持久 |
| --- | --- | --- |
| 字段 | 必填、格式、范围、服务端字段错误 | 直到修复 |
| 表单 | 提交失败、版本冲突、权限、跨字段约束 | 直到处理 |
| 局部 | 某一行/区块刷新或操作失败 | 直到重试/关闭 |
| 页面 | 首次加载失败、部分数据不可用、批量汇总 | 直到恢复/关闭 |
| 全局 | 登录失效、服务降级、全站只读 | 直到恢复 |
| Toast | 复制成功、已保存等短暂且非阻塞结果 | 短时 |
| 任务结果 | 发布、部署、批量操作和长任务 | 可追踪到终态 |

危险操作在请求前使用确认弹窗；高影响结果使用结果弹窗或任务抽屉。确认、请求接受和最终完成不得混为一个状态。

### 7.4 格式化

建立单一 formatter/adapter 层：

- `formatDateTime`、`formatRelativeTime`、`formatBytes`、`formatCurrency`、`formatRate`、`formatMultiplier`；
- 所有状态值由领域字典转换，未知值显示“未知状态（原值）”并保留复制入口；
- 错误经过稳定错误码映射，原始错误放入可展开技术详情；
- JSON/模板/日志使用专用 Viewer/Editor，明确 UTF-8、换行、行号、复制与敏感字段处理；
- 空值统一使用 `—`，不把 0、false 和空值混淆。

### 7.5 请求状态

统一 `useQueryState` / `useMutationState`：

- 首次加载、后台刷新、局部刷新分离；
- 新请求取消旧请求，或通过请求序号拒绝过期响应；
- 读取可重试，写入具有幂等键或前端重复提交保护；
- 列表更新优先局部替换，避免每个行操作后重新下载所有数据；
- 长操作返回 operation/task ID，通过事件或受控状态查询进入统一任务中心。

## 8. 统一列表 API 契约

### 8.1 请求

稳定资产列表使用：

```text
GET /api/v1/admin/<resource>
  ?q=
  &filter_name=value
  &sort=field:asc,field2:desc
  &offset=0
  &limit=50
```

高频追加的运行日志使用 cursor，避免翻页期间重复或跳行。

### 8.2 响应

```json
{
  "items": [],
  "page": {
    "offset": 0,
    "limit": 50,
    "total": 0,
    "next_cursor": null,
    "previous_cursor": null
  },
  "aggregates": {},
  "facets": {}
}
```

- `items` 只包含列表所需摘要；配置、历史、密钥状态细节按 ID 加载；
- `aggregates` 为当前筛选范围的汇总，不由当前页数组推算；
- `facets` 提供状态/区域等可用筛选计数；
- 关系选择器使用独立轻量 lookup API；
- 一页查询的 SQL 数量必须为常数，禁止对每个 item 再查统计。

## 9. 节点工作台样板

### 9.1 默认结构

```text
┌ 节点资产 ───────────────────────── [刷新] [登记节点] ┐
│ 搜索名称/IP  区域  生命周期  在线  SSH  内核  [更多筛选] │
│ 已选 3 项                  [批量检测] [维护模式] [更多] │
├ □ 名称/IP ─ 区域 ─ 生命周期 ─ Zero ─ SSH ─ 内核 ─ 协议 ─ 最近心跳 ─ 操作 ┤
│ □ HK-01 ...                                                        │
│ □ JP-02 ...                                                        │
├ 第 1–50 条 / 共 1000 条                         50/页  <  > ┤
└──────────────────────────────────────────────────────┘
                              ┌ 节点详情抽屉（URL: node_id=...） ┐
                              │ 概览 | 运维 | 协议 | 凭证 | 历史 │
                              └──────────────────────────────┘
```

### 9.2 列与筛选

默认列：名称/默认地址、区域、生命周期、Zero 在线、SSH、内核状态、启用协议数、最近心跳、行菜单。

高级列：Zero 版本、平台架构、最后检测、凭证状态、创建/更新时间。

筛选：区域、生命周期、启用状态、Zero 在线、SSH 配置/验证、内核健康、是否承载协议、异常类型。

### 9.3 详情加载

- 概览从列表摘要立即显示；
- 打开“运维”才加载内核状态和最近操作；
- 打开“协议”才分页加载该节点端点；
- 打开“凭证”只加载脱敏状态，不预取或回显秘密；
- 切换节点取消旧详情请求，响应必须校验 node ID；
- SSH 终端、重新信任、凭证轮换放入分组操作菜单，避免标题区按钮堆叠。

### 9.4 节点 API

```text
GET /admin/nodes?q=&region=&lifecycle=&connector=&ssh=&kernel=&sort=&offset=&limit=
GET /admin/nodes/:id
GET /admin/nodes/:id/kernel
GET /admin/nodes/:id/protocol-endpoints?offset=&limit=
POST /admin/node-operations       # 批量检测/维护等，返回 task_id
```

列表统计通过 JOIN/子查询批量聚合，不能逐节点读取状态。

## 10. 协议工作台样板

```text
┌ 协议服务 ─────────────────────── [刷新] [创建服务] ┐

│ □ HK VLESS ...                                                        │
│ □ JP HY2 ...                                                          │
├ 第 1–50 条 / 共 5000 条                              50/页 < > ┤
└─────────────────────────────────────────────────────────┘
                          ┌ 服务详情抽屉 ───────────────┐
                          │ 概览 | 配置 | 发布 | 使用 | 关联 │
                          └─────────────────────────────┘
```

### 10.2 行为

- 默认按“发布失败、运行异常、长期未使用、正常”排序，异常优先但允许改回自定义排序；
- 错误只在行内显示一行摘要，完整错误、输出、哈希和重试记录进入发布标签；
- 创建使用三步向导；查看与编辑分离，打开详情不自动进入可写表单；
- 批量发布返回任务 ID，行状态通过同一任务结果更新；
- 倍率快速编辑使用行内小型表单，但失败保留在当前行；
- 按节点分组是可选视图，不替代默认表格。

### 10.3 协议 API

```text
GET /admin/protocol-endpoints?q=&node_id=&region=&protocol=&active=&deployment=&sort=&offset=&limit=
GET /admin/protocol-endpoints/:id
GET /admin/protocol-endpoints/:id/deployments?cursor=&limit=
POST /admin/protocol-deployments/batch
PATCH /admin/protocol-endpoints/batch
```

端点用量必须一次批量聚合；最新部署通过子查询/窗口查询批量关联，不再请求“最近 200 条全局记录”后由前端猜测。

## 12. 验收基线

### 12.1 规模与性能

- 数据集：1000 Nodes、5000 ProtocolEndpoints，并包含足够的部署、流量、任务和审计历史；
- 浏览器任一列表默认最多渲染 50 行，允许 25/50/100；
- 列表 API 不返回完整配置、日志正文或秘密字段；
- 一页列表查询 SQL 数量为常数，不随行数增长；
- 内网环境常用列表请求目标 p95 不超过 800ms，首屏可操作目标不超过 1.5s；
- 快速切换筛选或详情不会显示旧请求的数据；
- 批量操作可追踪、可重试，并明确部分失败。

### 12.2 交互

- 筛选、排序、页码、密度、选中对象和详情标签可由 URL 恢复；
- 加载、空、错误、无权限、部分数据和刷新中状态均有独立呈现；
- 所有提交具备重复提交保护，危险操作说明准确对象与影响；
- 字段错误就地显示，首个错误获得焦点，弹窗失败不使用全局 Toast；
- 后台任务区分请求接受、执行中和最终结果。

### 12.3 可访问性与浏览器

- 键盘可以完成筛选、表格行选择、分页、抽屉、表单和确认；
- Dialog/Drawer 焦点陷阱、关闭和返回焦点正确；
- 排序、选择、错误和异步状态具有可读 ARIA 状态；
- 1440px、1024px、768px 和 390px 宽度不存在不可达操作或页面级意外横向溢出；
- 使用真实登录态逐页点击，不以 build/typecheck 代替交互验收。

### 12.4 工程验证与部署

- 前端 typecheck/build、Go tests/vet 和差异检查通过；
- 添加针对列表契约、批量聚合、错误映射和 URL state 的自动化测试；
- 结果与已知缺口写入 `PROJECT_MEMORY.md`；
- 按仓库流程同步内网，并验证版本、`/readyz`、容器健康及目标页面行为。

## 14. 已确认的产品取舍

以下规则已于 2026-07-22 确认，作为全部管理端页面的共同约束：

1. 节点默认使用“全宽表格 + 右侧详情抽屉”，提供可选固定分栏，而不是始终显示左侧节点按钮列表。
2. 协议默认使用紧凑表格，按节点分组仅作为可选视图，不再以完整卡片列表为主。
3. 管理表格默认 40px 行高、每页 50 条，允许切换 25/50/100 和舒适密度。
4. 详情抽屉宽度默认 560–720px；复杂编辑进入大弹窗/全屏工作区，查看详情与编辑分离。
5. 筛选、排序、页码、当前对象和标签全部写入 URL；返回列表保留上下文。
6. 协议发布、节点检测和批量操作统一进入任务体系；点击成功只表示请求已接受，最终结果持续可见。
7. Dashboard 指标只保留可以直接进入处理队列的数字，取消纯装饰或基于当前页数组计算的指标。
8. 业务状态统一使用“语义图标 + 文字”的紧凑标签，不再只输出裸文字、只用颜色或只显示无说明图标；未知状态保留原值和可诊断入口。
9. 数量列直接显示便于纵向比较的数字，单位和统计口径放在列标题或字段标签中，不在每一行重复拼接说明文字。
10. 时间默认显示经过格式化的紧凑标签：近期时间优先显示相对时间，悬停、聚焦或详情中保留带时区的精确时间；不得直接输出后端原始时间字符串。
