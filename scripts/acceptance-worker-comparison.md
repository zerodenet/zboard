# 独立投影进程的相同预算比较

`acceptance-worker-comparison.py` 为 P6 提供可复现的比较入口，不启动自动伸缩。原 `acceptance-mixed.sh` 仍使用默认 1CPU/1GiB、原请求延迟、700MiB 工作集和磁盘门槛，必须单独通过，不能由本比较替代。

两个比较方案的总配额均为 1.5CPU、1536MiB、无额外 swap：

| 方案 | 主进程 | 投影进程 |
| --- | --- | --- |
| single | 1.5CPU / 1536MiB | 无 |
| split | 1CPU / 1024MiB | 0.5CPU / 512MiB |

使用相同的一份二进制，每次新建隔离 SQLite 夹具，默认三个配对、交替次序。每轮为 2 节点、20 订阅、2000 条历史、60 秒、20 事件/秒、4 个读取客户端。请求、账务、统计、spool 和磁盘仍执行原断言；两个进程合计采样工作集也必须不超过原 700MiB。记录各进程 CPU、工作集、RSS、真实资源限制、退出结果，保留原运行诊断中的数据库等待、接收到结算延迟及积压。资源观测失败显示未知并使该轮失败。

先在无其他本地构建/测试的窗口编译；工具不会清理任何缓存。可在编译完成后独立维护已获授权的可再生缓存，再用同一构建回执执行，二进制和源码必须仍匹配：

```sh
python3 scripts/acceptance-worker-comparison.py --checkout "$PWD" --revision "$(git rev-parse HEAD)" --prepare
python3 scripts/acceptance-worker-comparison.py --checkout "$PWD" --revision "$(git rev-parse HEAD)" --execute /path/to/printed/build.json
```

不指定执行参数时只检查并打印来源绑定；必须是已提交、未修改的后端和验收源码。正式执行的实际 spool 储备分配后仍要求至少 1677721600 字节可用空间；未满足时不启动负载。任何失败停止后续比较，不自动重试，不放宽门槛。`--pairs 1` 可调试入口，但不能用一个短样本证明稳定收益。

只管理该次调用创建并逐项核对归属标签的容器与测试卷；先导出原数据库，再处理夹具。导出失败或归属不确定时保留资源，记录后续核对对象。保留镜像、源码、日志、数据库副本及所有失败证据；不接触既有容器、卷或数据库。镜像和保留副本占用空间须计入下一轮预算。

`comparison.json` 提供每轮明细及 drain、合计工作集的中位数，始终不自动声称 `benefit_verified`。需要同时检查核心接口 p95、实际积压/结算延迟、CPU、RSS、数据库等待及额外成本。如果低负载下主进程已经足够，启动另一个进程本身没有证明收益。该入口及单独 worker 都不等同于本机自动伸缩、数据库慢写防扩容风暴或插件繁忙资源保障已经完成。
