# 旧订阅取消入口收敛到整份终止

本小批针对现存`subscriptions.status.cancel`管理能力。旧实现只改`canceled`并撤销部分凭据，没有同时关闭订阅token、自动续费、待付款资金预留及历史订单的剩余权益；与新整份退订入口存在状态差异。`OrderTransitionAllowed`本来已经禁止paid→canceled，不修改该保护。

## 实际入口与唯一写入

应用组合层将旧cancel命令接入commerce的来源订单→按ID排序的账户/当前管理员→订阅锁定和同一`finishSubscriptionTermination`。延期仍走原entitlementstore；旧适配器拒绝新的cancel写入，保留已存在回执的授权读取。没有第二条扣款、退款或权益终止写入路径。

旧入口原本不接受退款金额，也不承诺退款。本批保留它显式零退款的运维契约，不根据默认残值暗中入账。需要默认残值或管理员自定义金额的退款，仍使用既有整份退订报价/确认接口；普通用户权限和插件支付事实权限不变。核心同时保存当前管理员、完整原因、插件来源、默认残值或未知、实际0元及原命令身份。

新命令终止所有剩余权益，撤销订阅token及所有未撤销凭据，关闭自动续费，释放关联未付款订单的预留并取消订单，在同一事务保存权益事件、审计和现有交付意图。真实支付及已用量历史保持，零元不创建退款账项、虚构订单、支付本金或金融结算；远端撤权仍是待核验状态。

## 兼容、持久化及回退

无新表、字段或SQL迁移。新回执在现有`subscription_mutations`中采用独立kind`cancel_without_refund`，原插件命令key/hash和原DTO保留；对应不可缺失的unsubscribe事件保存完整默认/实际金额证据。共享指纹函数严格保留旧JSON序列化身份，并用固定历史样本校验。新回执缺失/损坏证据时失败，不当作旧回执成功。

历史kind`status.cancel`回执只按原身份返回历史；不因重放而偷偷执行新的生命周期效果或退款，也不宣称旧数据已完成整份终止。旧不完整记录的单独核对/修复仍是后续事项。报价只读，数据库错误继续失败，不能将数据库故障归为未知残值并承诺成功。

回退先停止新cancel命令入口及相关在途执行，保留全部命令、事件、资金、订单及交付记录；本批无schema回滚。不能回到旧状态写入器后继续宣称整份终止的保证；应保留读取兼容并禁用该入口，再调查恢复。没有生产迁移、真实退款、发布或合并。
