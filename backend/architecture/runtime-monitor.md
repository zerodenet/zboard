# 面板运行监控：分钟持久化与固定保留预算

## 采集和展示

后台独立采集本实例每 5 秒一次，页面每 15 秒读取已有快照。页面开关和访问人数
不增加采样任务或持久化任务。主机 CPU/内存、实例可见的根文件系统、ZBoard 进程
占用分别计量；容器内网络为实例网速，不冒充宿主机总网速。未知值保持未知，
计数回退中断差值，不能画成真实零。

图表使用五条曲线、百分比与网速双轴、同一时间的垂直读数、十字线和圆形标记。
分钟值是均值，不代表秒级最大值。缺失点和采集中断同时打断折线与填充，空白
时段不吸附到很远的旧记录。刷新保留所选时间，提示框受图表边界约束。布局按
实际内容宽度切换，轴和元数据至少 11px。

## 持久化及容量边界

独立的 `runtime_metric_minutes` 表保存 UTC 分钟聚合，不保存秒级明细、原始报告、
每次访问或进程启动流水。表只包含固定类型的时间、数值总和、计数等字段。

- 分钟映射到 `unix_minute % 1440` 槽位，槽位是主键；数据库 CHECK 约束限制范围
  为 0–1439。即使清理中断、反复重启，也不能持续新增历史行，最多 1440 行。
- 正常写入已结束分钟，约每分钟一次事务；分钟内的 5 秒采样只更新内存。
- 保存每个指标的总和与样本数。正常退出补存当前部分分钟，重启后恢复权重，
  继续同一分钟时不会重复创建记录或用新样本替换已保存样本。
- 启动读取及后台写入都删除超过 24h 的行；读取同样限制时间和行数。过期淘汰
  不依赖管理页面是否打开，不建立归档或备份副本。
- 回补最多 1440 个未过期分钟，按 100 行生成批次，整体事务原子提交。过期分钟
  从内存和待写集合移除；不会为长时间数据库故障建立无上限队列。
- 条件 UPSERT 先校验分钟和样本数，再更新字段，最后更新样本数与分钟时间。
  旧重试不能覆盖更晚的槽位记录，也不能使同一分钟聚合倒退。

该表表示当前单实例面板部署的监控序列，不承担跨主机、多租户时序采集。

## 生命周期和故障

应用启动后先恢复保留历史，再开始采样；数据库操作有 2 秒时限。持久化工作
与采样循环分离，数据库阻塞不会让采样一直等待。首次恢复失败时不能直接覆盖
数据库原有历史：先继续有上限的本地采样，恢复读取成功后合并并回补。

API 返回持久化状态、最后已保存的分钟和待写分钟数。失败时保留曲线并就近
提示自动重试，不能把内存数据当作落库成功。查询 API 只读内存，不由页面轮询
触发保存或清理。

正常关闭停止采样和工作循环后补存当前分钟。强制中断可能损失正在聚合或提交、
尚未落库的采样；已提交的历史可在重启后恢复。数据库故障期间无法承诺未提交
采样在强制中断后仍存在，状态必须如实报告失败。

## 升级和验证

`0082_runtime_metric_history` 为新小表，MySQL 和 SQLite 各有 SQL 资产。统一迁移
入口校验列、主键和容量约束，可在 DDL 已完成但迁移记录未写入时恢复，保留
既有监控记录，不重建大业务表。

本地验证包括：真实数据库文件关闭重开、全新采样器恢复曲线、同分钟均值续算、
固定槽位及约束、长时间故障待写上限、物理过期删除、事务失败回滚、旧重试保护、
中断迁移恢复和 MySQL 方言 SQL 生成。前端验证失败状态可见且实时数据与曲线保留。
MySQL 实例上的实际迁移和服务升级属于后续明确部署验收范围。

本轮仅本地实施与验证，不构建版本、不提交推送、不部署生产。
