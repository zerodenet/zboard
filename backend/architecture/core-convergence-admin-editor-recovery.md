# Ordinary administrator drafts across reauthentication

This increment connects the shared same-account recovery boundary to node/group metadata, public site/registration/email-template settings, public policy/legal documents, announcements, menus, uncreated operational tasks, DNS and certificate editors. It adds explicit view-specific allowlists, fresh resource reads and the original version/baseline. It never restores a task's execution/approval state, immediately sends mail, issues a certificate, deploys DNS, installs a node or generates a Reality key.

Sensitive configuration is not scraped. SSH credentials, provider tokens, private keys, ACME material, one-time secrets, SMTP, takeover approval and in-flight install/BBR state remain excluded. Ordinary text bodies are preserved verbatim within the shared recovery budget. Unsupported structure, invalid JSON or a large envelope refuses full-page navigation and keeps the original mounted content; data is not truncated to fit. Policy and legal drafts capture only five known public keys with public/nonsecret/type metadata, including their original JSON strings and revisions.

Existing server CAS stays authoritative for groups, DNS, certificate and public configuration revisions. Nodes and site identity currently lack a write CAS: fresh baseline comparison protects changes observed across reauthentication but does not make a later concurrent PUT atomic. Conflicts keep the old draft visible and disable both the button and direct submit handler. Fresh GET failure keeps the stored payload for retry; actor/token/session/route/editor-generation changes invalidate a late response. Original evidence survives another reauthentication instead of silently adopting a new revision. Menu immutable owner/plugin/page/condition metadata comes from the fresh server tree. Operational tasks resume with immediate execution off and require explicit target review.

Actual local checks with unchanged frontend source per run: node/settings integration 153 tests plus build; communication recovery 35 tests plus build; legal/managed integration 53 tests plus build. The unchanged main frontend scope is still to be rerun after the remaining editor integrations. No new baseline exclusions were added. Earlier communication tests reused one mutable mock response across independent HTTP calls; each call now returns a fresh clone while all authority and permission assertions remain. The legal shallow-mounted button fixture now exposes its inner native button, retaining disabled/programmatic/revision assertions. Original failures and logs remain preserved.

Real-browser/OAuth, external DNS/ACME/plugin and final-head CI acceptance are unexecuted. Other editor recovery is a separate increment; this record does not claim P5 or overall P0–P7 completion. No production/user-machine operation, financial write, permission expansion or migration occurred.
