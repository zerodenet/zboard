# 流量结果、有限历史与补报身份

实现日期：2026-11-12 至 2026-11-13。代码尚未构建、发布或应用到生产。

## 范围

本轮在现有上报协议下落实结果汇总、有限历史、精确冷身份和迁移恢复。
观察链路复用已提交的 0085 mailbox，不提高原 64MiB 原文容量来维持统计。
新增 0086–0088；不新增 Redis、消息中间件、离机归档或生产备份依赖。

当前协议仍允许独立随机报告 ID，以及任意久以前的连接累计值增加。
因此，必要的去重身份和连接 floor 不能单靠年龄删除。本轮压缩其表示，
不承诺全部财务存储恒定，也不以 MAX(sequence) 替代完整身份。

## 写入先聚合

计费仍先按既有样本顺序求增量、舍入并封顶，再合并已经确定的数值。
`metering_settlement_results` 按用户、订阅、权益代次、节点、协议、计量方向和倍率保存结果；
它与额度、报告身份、投影意图在同一个入账事务提交。

新原生聚合来源使用接收日分区，并按订阅锚点的完整时分秒切为两侧。
所有受支持的日历月/年、购买日月/年重置边界，都位于 UTC 日界或这个锚点位置。
这消除了无必要的接收分钟维度，同时保留精确重置核算。接收时间与发生时间分别处理。

发生时间已过期的补报直接进入仍有意义的粒度：24 小时内分钟、30 天内小时、
365 天内日；更老的报告只维持可重放的数值来源与业务结果，不重建过期图表。
此类来源的 `history_resolution=expired` 明确表示原始发生时间详情已到期，
内部固定时间值不作为原始事件时间展示。新补报照常扣量，原报告重放不再扣量。

MySQL 的 `ON UPDATE CURRENT_TIMESTAMP` 不得因覆盖标记改变原接收/证明时间。
0086 的覆盖写入显式保持每条来源原时间，原生聚合保持最早接收及最晚修改时间。

## 回填、合并和淘汰

0086 只捕获旧账本主键上界；后台每批最多 200 条转换，不在启动时扫描历史。
结果读取为“已覆盖结果 + 未覆盖旧来源”，转换标记、结果和游标原子提交。
活跃旧桶在回填前继续留在旧来源，回填后新增增量进入结果，避免漏记或重复。

账本来源按接收冷却时间逐步合并到小时、日，最后只保留结果。
当前仍可能参与精确额度重置的接收周期不会被越过；跨边界而无法证明的旧桶保留。
合并累加已扣量，绝不重新对聚合原始字节计算倍率。来源的投影未完成时不得移动。

独立小时投影只留 30 天，协议日投影留 365 天。超期投影分批按索引键删除；
迟来的历史报告和图表重建都不复活过期桶。更老的保留期内图表从分层账本读取。
重复执行、失败和重启均使用持久化进度，不重新累加已转换来源。

尚未核验的计费证明保留原始记录，并在一个固定进度行记录数量和最近原因。
其他可核验来源继续转换；只在一轮结束时报告汇总问题，避免每条坏数据生成一份永久辅助记录。

## 精确冷身份

原报告回执、旧 API nonce、连接 floor 和账本转移引用进入共享的有界冷页表示：

- 完整数据库等价身份、完整必要原键、精确整数采用前缀和变长编码，再 gzip。
- 每页最多 512 项、未压缩 256KiB，校验正文摘要和页头摘要；解压有硬边界。
- 目录使用可分裂哈希前缀路由，真正判重仍比较完整数据库等价键。
- MySQL 延续原字段的大小写、重音和 PAD SPACE 规则；SQLite 支持其既有 BINARY/NOCASE/RTRIM。
- 1KiB 过滤器只用于排除确定不存在的身份，且先核对绑定它的页头校验和。
  命中必须完整解码核对；过滤器不能独立决定已经计费。
- 新报告的负向探测可复用事务内校验过的页头；正常新流量不必反复解压旧历史。
- 转换每批最多 200 个候选，按页批量归并；超过 8MiB 转换读取预算时缩小批次重试。
- 预计算数据库等价键在短节点转换栅栏之前批量完成；栅栏排队获取，避免忙节点永久跳过。
- 新段先写并读回验证，再在同事务移除旧热行。损坏、缺页或冲突不会被视为从未入账。
- 旧连接只有首次更高累计补报才重新打开一个有界页；之后恢复热写。
  原 floor 的移除与新热 floor、扣量、结果同事务，重复或低序号重放不重扣。

冷页转换按节点隔离：损坏节点保留原件和简短诊断，健康节点继续处理。
永久删除并已撤销两种节点凭据的资产，可按既有终止准入规则回收冷连接 floor；
一般活跃节点没有历史补报截止时间。

## 读取与复制

对账使用业务结算结果，不依赖图表历史。重置仍读取被保护的精确接收周期来源。
公共历史接口提供 `history`：实际窗口、可用粒度、保留起点、是否过期及必要日历说明。
详情到期不能冒充零计费用量。后台和用户中心共用简短精度/过期提示，日汇总明确 UTC。

当小时或日精度已不能表达时区的部分桶边缘时，历史日历明确按 UTC 输出。
请求身份和请求日期仍保持原响应契约；实际可用范围、日历由 `history` 描述。
当前仍具备精度的当地日界、DST 和四分之一小时时区读取保持原有精确路径。

所有表加入正式迁移、准备校验和复制清单。已经记录的权威表或检查点丢失时拒绝启动，
不把它们静默重新创建为空。账本最高已分配 ID 单调保存；复制用事务内零值分配栅栏
保留这些 ID，不用会隐式提交的 AUTO_INCREMENT DDL，也不留下业务哨兵记录。

已封存身份的跨不同排序规则复制会在写入前拒绝，要求专门核验的重建键空间转换。
没有封存身份时，空的编码配置可按目标数据库初始化。相同规则的 SQLite/MySQL 复制已覆盖。
已经删除低层详情后，不能简单换成不认识结果和冷页的旧二进制；降级 SQL 明确拒绝。

## 上报契约核验与未启用能力

核验现有 Zero `ApiEvent`（`crates/api/src/event.rs`）与 ZBoard `FlowUsageKey`：
存在运行代次和可选发布序号，但当前计费仍是逐连接累计 floor；序号不证明所有原始样本
已连续入账，也不是带计费边界、舍入证据与离线恢复保证的主体累计流契约。
本轮没有修改 Zero 仓库、强制升级节点或启用“永久删除所有旧身份”的模式。

进一步从“随独立连接/随机身份增长”变成“只随计费主体增长”，仍需要上报端完成并协商
可验证的累计计费流契约，再做逐样本差分核验。当前兼容模式的压缩存储仍随必要身份数增长。
这项边界不能用加大容量、Bloom 误判、序号最大值或未经证明的去重 TTL 掩盖。
