# Principal observations preserve opaque runtime identity

0069 complements 0068 for the four indexed principal generation/current/observation/scope-history tables. It retains complete raw identities in MySQL MEDIUMTEXT; generation/current prefix indexes are nonunique performance aids. Observation uniqueness uses a separate ASCII SHA256 column plus the original node/revision/principal fields. A digest-looking short literal cannot alias a long raw identity. Full raw values are compared before accepting a duplicate. No identity is replaced by its hash in native control, financial cursors or proof material.

Owned migration verifies nonempty stored digests and backfills only empty values in bounded pages, creates and verifies the replacement complete unique index before removing the old one, and resumes interrupted atomic ALTER steps. Missing recorded tables/columns or weakened unique indexes refuse startup/copy. Legacy copy computes a missing digest only in the prepared owned destination; it does not mutate the source. Raw reads check byte metadata first, with 2 MiB per identity and 8 MiB per event; copy uses 0068's 4 MiB raw batches. The existing HTTP body limit remains 1 MiB: the wider internal read budget is not an expanded wire contract.

MySQL duplicate detection uses a normal insert and only the typed duplicate-key error. It does not infer first insertion from affected-row counts, which CLIENT_FOUND_ROWS changes for no-op upserts. Exact unique-identity metadata and full reads use current SHARE reads so an older transaction snapshot does not reject a newly committed legitimate identity. SQLite keeps its existing conflict behavior. Other errors are preserved; no INSERT IGNORE, transaction-isolation change or automatic business retry is added.

New dual-database fixtures cover long shared prefixes, digest-looking short identities, generation/revision/stop/late/restart/replay, changed raw/digest proof, actual CLIENT_FOUND_ROWS and an established repeatable-read snapshot, partial migration/backfill, prepared legacy copy, damaged authority/index refusal and oversized material rejected before full reads. These tests are unexecuted locally because required dependency downloads return HTTP403. Go formatting parsed the code and the 75 ownership/architecture tests passed after integration; these checks do not prove database behavior. New-head CI, actual SQLite/MySQL/race and the expanded P7 backup/restore probe remain required.

No production migration, historical row deletion or physical shrink occurred. Down SQL preserves accepted identity/index evidence. An older writer is not certified compatible with new digest uniqueness: use a complete verified backup and reconcile subsequent facts before rollback. Observation history and necessary business authority may still grow with accepted events; this fix does not claim a fixed total database size or completed capacity acceptance.
