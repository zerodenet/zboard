# Bounded runtime measurements for local worker acceptance

The existing opt-in administrator runtime endpoint now exposes actual durable job-store Claim/Finish latency samples and native authority-transaction statement observations. Both use fixed 64-entry rings. Missing/stale samples remain unknown with nullable timing fields. No per-user metric maps, new database table, permission, billing rule, retry or execution timeout is added. The existing database-pressure decisions continue to use their original measurements and thresholds.

The native observer installs fixed GORM callbacks once, then records only contexts explicitly scoped to the existing buffered native authority transaction. Ordinary queries do not allocate collectors. Observations include attempted statement categories, callback errors/read misses, driver-reported write rows, text/BLOB argument bytes and source payload bytes. SQL text, parameters and subject identities are not retained. Instrumentation failure cannot add an error to the business transaction. Transaction completion is confirmed only after the existing Transaction call returns nil; errors remain commit-unknown rather than claiming rollback.

These figures exclude driver BEGIN/COMMIT, preparation, deferred Row consumption, auxiliary coverage/projection, other processes, indexes, WAL and physical storage write bytes. Claim/Finish duration includes adapter and SQL work; it is not server-only SQL latency. The acceptance report must preserve these scopes and reset/sequence/freshness markers when comparing cumulative counters. A metrics endpoint alone proves neither capacity nor a worker benefit.

Actual local checks: 77 complete localworkers/jobs tests passed without skips in 2.408 seconds, with unchanged relevant sources. The production batchsql package compiled in 2.008 seconds with unchanged sources. New actual SQLite/MySQL six-processor/rollback/observer-isolation and native handler tests are present but unexecuted locally because datastore/compression dependencies cannot be downloaded (HTTP403). The dynamically inventoried MySQL core profile includes the new TestMySQL batchsql case; no new exclusion is added. YAML parsing also caught and corrected an unquoted comma in one new inline description; full OpenAPI validation remains required.

Full backend/SQLite/MySQL/race, final-head CI, equal-budget worker comparison, real slow-write/plugin-busy/crash/scale/drain scenarios and physical database growth measurements remain separate required evidence. No production or user-machine execution occurred.
