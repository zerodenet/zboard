# P6：可选的本机投影进程监督

本批把同一程序的 `-projection-worker` 接入主服务中的受控监督器。默认 `-projection-workers-max=0`，完整核心仍在一个进程中运行；默认不创建监督锁、不查询容量状态、不启动子进程。独立进程只处理既有 usage/node observation 投影，不启动 HTTP、插件、schema/default/bootstrap/凭据迁移或事件 spool。支付、权益、配置发布和计量事实继续由原应用能力及事务负责。

## 运行和部署边界

管理员可在同一完整主服务上显式配置：

```sh
./zboard -f /etc/zboard/zboard.yaml \
  -projection-workers-max=1 \
  -projection-workers-lock-file=/var/lib/zboard/projection-workers.lock \
  -projection-workers-database-path=/var/lib/zboard/database \
  -projection-workers-confirmed-benefit=false
```

上述路径只说明接口，应选择部署实际存在的本机数据库目录及单一私有锁路径，不据此自动操作生产。`confirmed-benefit` 是管理员对该部署已经完成等预算基准的声明，默认 false；程序不把该声明称为自动证明，也不改变现有比较工具的 `benefit_verified=false`。未确认时不扩容。相同声明为 true 仍不能绕过 CPU、内存、IO、存储、数据库、队列新鲜度及执行预算。

MySQL 最多四个额外受管进程，SQLite 最多一个；两者不宣称相同性能。对远端/不可定位数据库存储、内存 SQLite、非 Linux 或不可读取的 cgroup v2，观测保持未知，不把任意本机目录当数据库余量。明确的非法 CLI 配置在准备数据库前拒绝；运行中监督锁忙/资源不可观测会解释增强能力不可用，完整单进程核心继续工作。所有主服务实例须共享同一数据库对应的本机锁文件。手动运行的其他 worker 不归此监督器撤销或杀死，仍受既有数据库全局预算约束。

孤立的监督参数（即使等于默认值）不会误启动普通服务；监督与 migrate、只读检查、旧版本 rollback 准备、报告补登记、证明归档/恢复、独立 worker 维护模式互斥。没有新增浏览器/插件授权入口。

## 实际采样和决策

固定窗口记录原 Runtime 的真实 durable Claim/Finish 耗时和完成错误，包含数据库提交/锁等待，不含 handler 工作时间和本机领取锁等待。空队列只读探测不能凑成成功写入样本；近期错误独立保留，后续成功不能立刻掩盖。窗口有界为 64 项，过期/未知不写成零负载。该观察只说明数据库调用状态，不说明任务业务执行成功。

usage/node Drain 另有固定八槽的在途存储观察，进入存储调用时登记，完成、取消或 panic 均清理；槽满/未知不得成为扩容许可。该耗时包含整个明确的投影存储能力调用，可能包含计算，因此与真正 Claim/Finish 提交延迟分开。父进程还通过一次最多三行的只读 JOIN 核对 system usage/node 资源当前 run/attempt，取得跨进程运行时长；Unknown、token/worker/时间不一致或重复资源保持未知。这样 child 内部长行锁等待不会因主 Runtime 的其他调用很快而被漏掉。默认投影存储/运行超过两秒只保守抑制扩张，不把长 handler 宣称为已测 SQL 慢写，也不凭该猜测撤权或重放。

监督器通过索引读取 usage 的首个 pending 主键、node observation 的首个可执行来源元数据及时间，不扫描历史统计、逐连接详情或大 Meta。每次主服务启动门及维护状态仍优先；维护或数据库失败只收缩自己的辅助进程。

Linux 采样使用 `/proc/stat`、`/proc/meminfo` 和按 /proc/self/cgroup、mountinfo 和当前PID成员核对得到的实际 cgroup v2 CPU 累计、配额、cpuset、memory.current/max/high。取主机与 cgroup 的保守压力，涵盖主服务、wazero 和本机 native 插件及子进程。IO-wait 和配置的实际 DB/spool 文件系统空闲量独立检查。CPU 不把 guest 时间重复计算，内存超额不发生 unsigned 下溢。CPU 计数回退、过期、缺失或不可读取均不能扩容。MySQL 还只读核对服务器连接上限与当前连接数，保留主池剩余预算和两个子进程连接；没有修改服务器变量或授权。缺少读取能力维持未知。

默认需持续三个健康积压样本、至少四个近期持久写入样本、最老可执行候选等待至少十秒，才可扩一个进程；两次健康扩容至少隔一分钟。CPU ceiling 0.75 之外还须容纳一个额外完整 CPU；核心/插件可用内存保留 1 GiB，每个子进程另预留 512 MiB，DB/spool 每个文件系统保留 512 MiB。近期调用达 100ms、连接余量不足、CPU/IO/内存/磁盘压力都会抑制扩容或减少受管并发。无可执行积压持续两分钟才收缩，避免瞬时队列空引发抖动。

上述阈值是管理员可调整的本机容量策略，与原验收脚本的磁盘、核心 p95、错误数、RSS 等门槛不同；修改策略不更改或替代验收门槛。

## 进程、锁和故障恢复

启动使用当前可执行文件和明确配置路径，经源文件身份及摘要核对，无 shell。文件变化后拒绝继续启动旧部署的子进程。每个受管子进程显式降低 CPU nice 优先级，使用 `GOMAXPROCS=1`、配置的 Go GC 目标，数据库连接进一步限制为最多两个（SQLite 保留一个）。Go GC 目标不是硬 RSS 上限，预留策略及优先级也不是已经验证的绝对 HTTP 延迟承诺。

监督器只掌握自己创建的 `exec.Cmd.Process`，固定最多四个槽。收缩先发 SIGTERM，复用原 `RunProjectionWorker` 的本机停领及在途排空；达到自己的排空预算后才中断自己的进程。没有调用全局 CancelHandler、删除 intent、解除 foreign lease 或改账。一个旧槽只有 Wait 确认退出才可重新使用。启动失败/意外崩溃产生有界递增冷却，不循环快速补进程。未知/未确认退出保留为未确认，不能冒充停止成功。

监督文件用 Linux `flock` 非阻塞独占，拒绝符号链接、非私有权限和其他所有者，不截断、删除或抢占旧文件。锁 fd 随子进程继承；即使主进程崩溃，未退出子进程仍保持所有权，新的监督器不能重复扩容。Linux parent-death SIGTERM 请求自己的子进程排空；创建线程保持到该子进程 Wait 完成，避免将普通 Go 线程回收误当父进程死亡。旧 worker 保持锁时，新主服务说明伸缩暂不可用并继续核心服务，原 spool 独占规则未改变。

默认子进程排空 8 秒，之后保留短暂强制退出核对窗口；监督器关闭还设排空预算加四秒的等待上界。异常文件系统观测阻塞时明确返回未确认，保留 Run/继承 fd 的所有权，不伪报退出；后续实际完成或父进程退出仍按已知句柄和内核信号规则处理。主服务再按原 shutdown 预算关闭核心、插件和 spool。扩大排空参数的部署必须配置相应进程管理器退出宽限。极端文件系统阻塞或退出未确认不构成重放/撤权许可。
