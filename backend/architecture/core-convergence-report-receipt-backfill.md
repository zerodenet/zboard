# P4：有界历史报告身份补登记

同一程序新增管理员本机维护入口 `-backfill-report-receipts`。它复用共享应用边界、当前物理 schema 核验和原报告身份写入规则，只把已有账务事实的身份登记到 0063 窄收据，不重新计算或扣减额度。

必须显式提供账务 ID 上界，每次最多检查 200 行；下界排除、上界包含。示例仅说明维护接口，不能据此直接操作生产：

```sh
./zboard -f etc/zboard.yaml -backfill-report-receipts \
  -backfill-report-receipts-after=0 \
  -backfill-report-receipts-through=500 \
  -backfill-report-receipts-batch=200
```

返回 JSON 中 `next_after_id` 只描述已确认提交的范围，下一次由操作者显式传回；不自动启动无限历史扫描。`scanned`、`identities_verified` 和 `unidentified` 分别表示读取事实数、核对身份数以及原事实本来没有可登记身份的数量，不把后者伪装成已覆盖。重放相同范围复用完全相同的账务行、节点、原报告 ID 和协议端点；任一身份冲突使本次事务中的新增登记全部回滚。无法确认数据库提交、连接关闭或命令输出时，应核对或重放同一范围，不声称未知结果必然失败，也不推进未确认的续跑位置。

查询只读取 ID、节点、报告 ID 和协议端点，不加载 Meta、金额、逐连接诊断或统计。原账务、nonce、倍率、逐报告舍入证明、FlowUsage、额度、统计恢复意图及已登记身份均不被改写或清除。不生成支付、退款、权益或配置交付事实。

入口先通过不创建文件的只读连接检查准备状态，再打开写连接，经应用入口重新核验；缺少 SQLite 数据库、缺失或损坏的身份权威状态、源主键或身份列均拒绝执行，不修复为空表。与 migrate、rollback、只读检查及 worker 模式互斥，普通服务启动不会自动执行它。孤立的维护参数即使恰好等于默认值，也会在配置加载前拒绝，避免误启动普通服务。不会启动 HTTP、插件、bootstrap、凭据迁移、任务执行器或文件 spool，也没有新增浏览器/插件权限入口。管理员需持有既有本机配置及数据库访问权限；部署 DDL 仍须先停止工作进程，本检查不是在线 DDL 的隔离锁。

范围耗尽不等于可以归档：尚未提交的较小 ID、旧二进制写入、未知历史以及其他账务/统计/nonce/累计游标读取者，仍须分别核对。该批没有增加迁移编号，没有启用删除或生产归档，也没有建立全库大小上限。中断后保留已有收据与原事实，重放已提交范围安全；回退二进制时继续保留 0063 和原账务事实。

专项真实 SQLite/MySQL 覆盖 205 行分段、范围重放、冲突整批回滚、禁止加载诊断正文及不越过显式上界；增加两个独立连接同时登记同一范围和源主键损坏的拒绝验证。主程序子进程验证端口被占用时仍能完成维护、重新执行幂等、既有配置/用户/任务计数不变、无 spool 创建。首轮夹具误拦测试自身 COUNT、误把迁移已有配置行当新增的三项失败保留；修正后首组 20 顶层/27 事件及架构 73 项、相同代码 race/count3 的 60 顶层/81 事件已通过；新增独立连接与参数保护的后续专项 21 顶层/28 事件及架构 73 项通过。源主键核验后的最终专项也已通过 21 顶层/28 事件和架构 73 项；最终相同源码的 race/count3、完整后端、原三组 MySQL 及新提交 CI 仍须取得自己的终态。
