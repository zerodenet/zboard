# P4：原生财务证明的有界封存与恢复

0064 只增加 `traffic_record_meta_archives`，把符合当前原生生成格式、已完成统计投影、全部源时间至少七天前的 `TrafficRecord.Meta` 按单行 gzip 无损封存。每个归档保留原始字节数、SHA-256、压缩字节数和绑定完整账务事实的摘要，后者明确包含对外 JSON 隐藏的 nonce 和权益代次。写入后在同一事务中重新读回、解压并核对，成功后才把原 Meta 改为版本化引用。所有金额、倍率、逐样本舍入依据、时间、报告身份、nonce、订阅用量和 FlowUsage 均不被重新计算或删除。MySQL 原 `updated_at` 被显式固定，避免 ON UPDATE 改写财务时间。

普通启动不封存，也不自动扫描历史。管理员本机显式执行：

```sh
./zboard -f etc/zboard.yaml -archive-metering-proof \
  -archive-metering-proof-after=0 -archive-metering-proof-through=500 \
  -archive-metering-proof-before=2026-10-01T00:00:00Z \
  -archive-metering-proof-batch=32
./zboard -f etc/zboard.yaml -restore-metering-proof=123
```

这些例子说明接口，不是生产执行授权。入口先用不创建文件的只读连接检查正式迁移和物理权威结构，再开 writer，并复用应用能力。与其他维护、worker 和受控伸缩入口互斥；孤立参数即使等于默认值也拒绝，避免误启动普通服务。不启动 HTTP、bootstrap、插件或事件 spool，没有给浏览器或插件新增直接写核心表的入口。

每次最多检查 32 个显式 ID 范围内的源；每正文最多 65,535 字节；每批把 live 正文、压缩输入、解压上界和写后核验都计入 1 MiB 材料预算，包括重复检查已封存引用。预算不足不推进对应源，也不提交半个封存。只在计入压缩正文、引用和保守 256 字节头/索引逻辑余量后仍净省超过 64 字节时封存，通常很小的证明继续内联。结果 `estimated_stored_bytes` 是逻辑字节估算，**不是 SQLite/MySQL 文件缩小量**。分配页、freelist、WAL/redo 和实际文件增长必须独立实测；本功能不 VACUUM、TRUNCATE 或清理现有库。

未知历史 JSON、旧可选诊断、超界正文、尚有投影意图、身份不一致及时间不可信的记录保留。旧可选诊断仍遵循原按需开启、容量和到期处理，不因本功能永久保存。`held` 是未取得封存许可，不能填成已覆盖或已归档。字节预算用尽时不会推进未读源的 `next_after_id`；`range_exhausted` 只描述本次显式范围，不是全库覆盖证明。任何事务或提交结果不确定返回空进度，操作者核对或重放同一范围。封存和恢复均幂等，恢复不删除归档证据。

计量、统计重建和对账仍读取原行的权威数值及身份。完整授权记录读取按原生账务 ID 查询 archive 权威头，不能仅凭可改写的 Meta.type 判断是否封存；非规范引用及损坏 type/key 均拒绝。已恢复 inline 原文与头中长度/SHA 一致时不再解压旧副本。legacy 的空 EventType 原文允许同名 type 诊断 JSON，不被解释为内部引用，封存时仍 Held。明确的汇总读取不读取或解压 archive。

完整原文读取另有独立的整次上界：最多 2000 行、8 MiB 证明输出和 16 MiB 材料（live + compressed + decoded）。无分页查询首先最多发现 2001 个薄 metadata 项，超限就在 Find 全行或解压之前返回明确的分页/缩小范围错误，不静默截断。正常分页全文也进行同样字节预检；常规 HTTP raw 表采用原分页汇总路径，不受这一全文证明限制。这不是把维护的 1 MiB 冒充读取预算。压缩炸弹、截断、尾随/多成员数据、错误哈希、错误事实绑定和缺失表/列均拒绝，不以空正文冒充正常。归档损坏不能使已经持久化的原生累计事实重新扣费：批量计量仍使用独立报告收据和累计游标。

已记录迁移的归档表丢失或变形时，启动和复制拒绝继续，不重建成空表；正式迁移中断且未记录时只接纳完全一致的物理结构。跨库复制清单保留二进制正文。旧二进制不能透明读取新引用，现有小时统计回退准备入口因此逐页按 archive 权威核对完整账务绑定和 live 原文长度/SHA，不能用损坏 type 前缀绕过；先停写，用当前二进制恢复并核对全部引用，再保留 0064 与归档证据回退。没有验证新业务写入后的生产降级。

该闭环控制证明正文的逻辑增长；权威账务行、报告身份和累计游标仍按真实业务增长。它不是全库固定上限，也没有证明可删除 TrafficRecord/FlowUsage 或任意去重状态。长期数据库/索引增长、归档覆盖缺口及完整容量报告仍需分开验收。

新增测试覆盖实际 SQLite/MySQL 迁移与二进制复制、新库/重复/已记缺表/部分列拒绝；原生真实累计事件 3×3 原始字节各自按 1.5 倍舍入为 3×5 计费字节，投影 pin、检查点失败、封存/恢复、损坏后重放、完整/汇总读取，以及有界未知材料与解压炸弹。本批代码尚待根代理统一编译、专项、完整后端、实库和精确 CI，未将写出测试当作通过。
