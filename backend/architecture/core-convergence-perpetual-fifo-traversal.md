# 永久额度 FIFO 的已耗尽批次遍历

基于85a6d1a，P2局部计算成本修复。每次后续购买前，原估值方法都从第一批开始消费新增用量，即使前面批次已经耗尽。1000笔来源的顺序购买需要反复访问这些零余额批次；既有1000笔证据上限没有改变。

## 实际变化和一致性

消费游标只向前推进，每个耗尽批次只经过一次。全部原始购买批次仍留在估值及报价指纹中，没有合并单价或按平均价格估值。每次消费仍发生在加入新购买批次之前，购买前超用不会消费未来购买；初次额度同步、零价批次、每批原实付和原整数舍入保持。

未改应用入口、权限、订单/账户/订阅锁顺序、事务、支付/退款/预留、持久化、幂等身份或任何SQL。无迁移或数据回填，回退二进制不会改变持久事实或旧报价身份。

## 实际验证和测量

原实现先增加同一套顺序购买夹具并测量，再改消费遍历。2/17/1000批次分别覆盖正常消耗和购买前超用；独立金额预期为仅最后批次剩余一半，按原规则半入。六个旧实现报价指纹全部逐字相同。1001笔仍拒绝，未放宽原安全上限。

最终完整commerce能力包56项顶层测试、零skip通过0.871s，vet通过2.135s。原实现同包通过16.232s含首次编译，不能把两个测试命令wall差异当性能收益。既有单批/多批FIFO、免费批、先前超用、舍入、旧证据、未知调整、回退计数及正常耗尽测试全部保留。
