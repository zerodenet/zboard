# 旧签名流量报告的诊断大小边界

P1/P4增量修复，基于本地b5c525c。旧签名报告的meta是上报者提供的可选诊断字符串，未参与身份、原始/计费流量、倍率、舍入或累计游标；原样写入已发布的MySQL TEXT。实际隔离MySQL8.4中65535字节能入库，65536字节触发Error1406，使有效计量事务整体回滚。

## 实际行为和事务

既有HTTP请求大小、签名、当前节点凭据、端点、单订阅/旧权益代次、report_id和nonce规则保持。原样保留最多65535个UTF-8字节；超限可选meta改存小于512字节的diagnostic_meta_omitted v1字符串回执，含text_byte_limit原因、原始字节数、上限和对解码后meta字符串的SHA-256。

摘要不能恢复原文，也不是计费或去重证明。原生累计计量Meta中的来源及舍入依据不调用这个方法，历史已入库记录不追溯裁剪。两个数据库使用相同字节边界，未改原始流量/计费流量、方向、倍率、逐笔舍入、剩余额度封顶或币种/金额。

节点/端点检查、原幂等身份、额度/流量账本和可靠投影意图仍同一事务。投影持久化失败仍整笔拒绝并允许核对重试；没有以辅助故障吞错冒充可靠接收，投影实际应用继续在后台完成。没有对普通用户或插件扩大写入口。

## 已验证

旧代码实际MySQL反例134.280s（含冷编译），保留TEXT过长错误和失败；未用SQLite假装该物理边界。修复后Go6顶层122.609s、真实MySQL2顶层13.776s均通过、零skip。

实际覆盖65535边界原文、65536字节、24000个三字节字符、原始长度/摘要、重复回执不再扣量、原nonce/凭据轮换/多独立订阅归属，以及原窄列投影保留Meta。3字节按1.5倍逐笔向上取整为5字节；三个报告15字节，注入投影意图失败不留账本/额度/nonce，显式重试后总20字节，后台投影也为20。

OpenAPI描述明确既有请求大小限制、字节边界和省略回执，Redocly1.34.3通过9.637s、282既有warning。Go和实际MySQL来源完全一致；随后仅澄清OpenAPI描述，所有Go字节未变，最终契约另验。前端/SDK未改。[完整命令/来源/用例/日志与原失败](validation/2026-10-23-node-report-diagnostic-meta.json)。
