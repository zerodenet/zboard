# 配置发布结果核对与重启恢复

发布记录是不可替换的配置意图。当前运行配置、某次发布是否曾完成、最新管理设置是否已经交付，必须分别确认。SSH 退出码或服务健康不能单独确认配置成功。

## 核对结果

| 证据 | 结果 | 后续行为 |
| --- | --- | --- |
| 回执的意图摘要、落盘文件摘要、进程身份和配置版本均匹配 | Applied | 只确认该发布原有的凭据交付范围；重新读取最新设置 |
| 同一进程的 applying 记录缺少更高版本的完成回执 | Unknown | 保留运行配置和凭据，只读复查，禁止重复应用 |
| prepared 尚未提交，或 pending 指向已结束的旧进程 | RetrySafe | 结束旧意图，正常编译并下发当前设置 |
| 后续成功发布的摘要与远端完成回执、落盘文件匹配 | RetrySafe | 旧意图已被替代；重启前回执不能直接确认新进程的交付状态 |
| 旧意图有完整完成回执，但回执进程已结束 | RetrySafe | 保留历史结果边界，重新同步当前设置并取得新进程回执 |
| 缺失、损坏、不匹配的证据，或核对期间进程/版本/文件变化 | Unknown | 显示具体原因，保留现场，不改写为成功 |

核对持有节点发布锁，前后两次读取运行身份及文件摘要；不调用 reload，不写配置、凭据或发布回执。新配置仍经原有验证、原生热应用和交付确认流程执行。无需升级 Zero 内核，也不以重启作为恢复手段。

## 持久化边界

- 同一节点只核对最新的未结束意图。任何仍在有效租期内的运行记录都会阻止抢占。
- 没有持久化配置摘要的过期草稿不可能开始远端执行，结束为 interrupted。
- 核对完成后，旧于该意图的未结束记录归为 superseded，保留原错误；新的意图不受影响。旧配置核对不会提前启用新凭据或改变计费事实。
- 后台每次最多补回 100 个节点缺失的持久化核对任务。保留已有队列的代次、租约、暂停状态及连接验证阶段；周期任务压缩历史。
- 连接验证发现旧回执不再属于当前运行实例时，只把自己拥有的队列代次交还配置阶段。连接验证本身不重载配置，也不能覆盖新意图。

## 可解释性与验证

失败原因区分发布锁占用、同进程应用未确认、进程重启但缺少完成证据、文件摘要变化、回执损坏或缺失、控制接口不可用、核对期间状态变化。错误包含待核对发布 ID；原始协议输出作为独立诊断材料保存，不把运行状态全文或凭据拼入错误提示。

回归测试执行真实核对 shell，覆盖确认丢失、重启、后续成功发布、同进程未完成、文件变化及读取过程中重启；持久化测试覆盖旧记录收敛、新意图隔离、缺失队列恢复与租约保护。后台节点详情就地展示完整核对原因，并可查看包含核对状态的操作记录。
