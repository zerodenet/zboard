# 有限优惠的排他预留与付款恢复

2026-10-27，P2/P5 增量。旧的纯报价 v1 保持兼容；有限库存、一次券的营销规则仍由插件实现。ZBoard 新增可选 `zboard.commerce.discount.redemption.v1` 原生宿主契约，SDK 提交 `b8bf14a9bff90c3154d962201ebdab4979eb98d9`。这不是支付真实性证明，也不授予插件修改核心表或履约权限。

## 权威状态及事务

只有严格接受快照的 `exclusive_until_core_finalization_v1` 标记要求预留。核心从已接受报价构造不可变订单/买家/价格/币种/原提供方/条款绑定，与订单在原创建事务中写入 0065 `order_discount_redemptions`。普通页面不能调用 Reserve/Commit/Release。未确认时不得创建收款尝试、预留/扣除余额、零金额履约或花费换购残值，也不改成原价。

外部调用在事务结束后进行。每次先 Query 原稳定 key；丢确认先核对，不换 key 重发。提供方必须提供线性一致的原 key 查询、持久排他预留、幂等 Commit/Release 和释放墓碑；不能自行按时间释放已确认的预留。已确认 token 丢失属于冲突，不能重新申请库存。首次尚未确认且可靠 Query 返回 absent 时只能重试同 key。提供方停用、超时、授权/签名变化均保持可解释的未确认状态。

核心付款和权益事务写入 Commit 意图，取消/失效/失败的原资金释放事务写入 Release 意图；退款不会把已核销优惠释放成可再次使用的券。默认未付款窗口沿用既有 30 分钟，已有资金预留保留其确定期限。周期任务与内联执行器复用同一条件租约/提交规则；进程在 RPC 后退出可 Query 恢复。已确认预留可在提供方暂离线时按原价快照付款，后续 Commit 后台恢复。

## 已有渠道付款与用户入口

旧渠道、订单、币种和实际渠道金额的匹配仍是收款入口前提。失效优惠不能获得新支付权；原已绑定尝试保留显式核对入口。核验成立的迟到款沿原账务处理进入余额或受控待核对状态，不复活已关闭权益。损坏/缺失优惠权威使可信付款事实进入 `review_required`；数据库写失败、事务失败或上下文取消仍返回失败，不能提前 ACK。

`OrderFundingPayment` 通过服务端 `can_cancel`/`can_reconcile` 显示合法取消和只核对原付款入口。`CheckoutPayment.reconcileOnly` 默认关闭；启用时不会创建订单、准备收款、弹外部支付窗口或自动重放写操作。显式核对刷新本站订单及余额，余额入账不显示成权益履约成功。身份/请求代次栅栏丢弃换账户后的旧响应。公开 DTO 不泄露预留 token、key、绑定、签名或安装修订。

## 升级、兼容与回滚

新增 0065，包含 SQLite/MySQL 正式迁移、恢复检查和数据库复制路径；未修改已发布迁移。迁移记录存在但权威表缺失时拒绝启动/复制，要求恢复，不能空建表伪造无预留。索引冲突、部分 SQLite 索引/表达式/排序/校对差异拒绝；中断后仅补可证明缺失的匹配索引。接受快照检查按 JSON 语义进行，包含转义和格式变化。

权威正文先查长度、再带长度条件读取，绑定最多 32 KiB、token 最多 512 字节。损坏行保留并延后，不能阻塞邻近健康任务。不会清理预留事实来绕过幂等。

二进制降级检查同时拒绝任何预留行（含终态）或已接受的新标记；旧严格读取器不认识该快照字段。必须用匹配代码，或在隔离环境按升级前完整备份恢复并核对所有订单/资金/外部副作用，不能在生产删除 0065 后运行旧程序。
