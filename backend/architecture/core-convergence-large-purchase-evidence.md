# P2：大量成交来源的证据处理

## 纯业务引擎首批

解除投影入口按1000条成交记录直接拒绝的限制，保留实际快照版本、支付真实性、逐批原价、FIFO消费、累计整数分摊和旧指纹。定期分摊改为单调区间遍历并复用同一frame的结果，避免原period×cycle的多层重复工作；定期逐事件重放最坏仍是二次复杂度，不宣称任意规模吞吐。单次4096期间/周期等既有校验保留。

新增可取消的共享入口 `ProjectEntitlementValueContext`，旧入口保持兼容。重放、FIFO消费及周期分摊检查请求取消；取消返回原context错误，没有部分可用报价。纯函数不负责数据库加载和来源锁，持久化入口的200行分页、正文与可变订单预算及超1000来源完整结算仍在后续批次验证，不能把本批当作购买/退款闭环已支持任意历史。

实际验证：Go1.26.8、GOMAXPROCS=2，`go test -json -p 1 ./internal/capabilities/commerce -count=1 -timeout 10m` 完整纯包188个测试事件通过，无跳过，wall19.432秒，执行3.177秒，源码前后哈希一致。既有<=1000来源golden指纹未重写；新增1200永久额度未用/部分用/耗尽/超用、1200定期来源及乱序输入、1101位置的未知证据拒绝和中途取消。该批没有数据库迁移、财务写入或生产动作。完整后端、MySQL与本批精确CI仍待独立终态。
