# P6：可选独立投影进程

默认仍由单进程运行完整核心。新增同一程序的显式入口：

```sh
./zboard -f etc/zboard.yaml -projection-worker
```

此模式仅运行已有 `usage_projection` 和 `node_observation`。它复用应用层的周期定义、公共 Runtime、数据库全局预算、资源互斥、租约、重试和幂等检查点；不另建队列，也不提高现有并发或批大小。原完整进程可继续注册这两项任务。多进程竞争由同一数据库身份处理，不能把多启动进程当作吞吐提升。

先在正常迁移流程准备数据库并初始化设置。worker 启动先复用 `-check-projection-database` 的不创建文件/只读检查，再连接写入池重新核对依赖。不会运行迁移、默认值初始化、凭据加密迁移或管理员 bootstrap，不启动 HTTP、插件、文件 spool 或节点控制连接。已有 prepared-schema 检查只证明两类投影的依赖，不认证整个数据库或未来二进制；修改 DDL 前仍须停止全部写入进程。

维护状态缺失、非法或不可读取时沿用既有 fail-closed 规则暂停领取。每个进程继续使用原固定执行池，跨进程全局预算和每资源限制保持。SQLite 每进程一个数据库连接，写入仍由其单写者规则串行化；MySQL 使用已有连接池配置，不声称两者性能相同。多个 worker 只支持同机部署。

收到 SIGINT/SIGTERM 后先停止本进程调度和领取，等待已进入的事务与任务完成。默认 drain 预算 30 秒，可用 `-projection-worker-drain-timeout` 设置 1 秒至 5 分钟。超出预算后按既有 Close/不确定结果规则取消本地执行并等待结束；预算不是驱动故障下的硬退出保证。退出不全局注销任务、不取消其他进程的租约，也不删除待处理意图。强制杀进程仍依赖原租约恢复，不能跳过未知结果核对。

`-projection-worker` 与迁移、小时统计回滚及只读检查三种独立模式互斥，在加载配置前拒绝冲突参数。正常服务启动路径保持原样。

行为测试覆盖双库实际投影竞争、维护暂停/恢复、停止一个执行器后另一个继续、其他持有者租约保留；实际 CLI 子进程验证端口已占用仍可运行、无 bootstrap/凭据迁移/spool，以及检查点提交失败回滚、后续独立进程恢复后恰好一次应用。测试中的故障和恢复是本机隔离模拟，不是内核、支付插件或生产验收。

本批没有自动扩缩容，也没有独立进程收益承诺。后续必须比较相同资源总预算下的单进程与独立 worker，记录 CPU/RSS、数据库等待、普通请求延迟和投影延迟；只有实测收益足以覆盖成本，才推进受控伸缩。数据库慢写时不能通过增加进程绕过预算。

无数据迁移。停止 worker 即可回到原单进程执行方式，不删除表、租约、检查点或业务记录。已经被强杀且结果未知的任务须依原规则恢复，不通过回滚二进制抹去。
