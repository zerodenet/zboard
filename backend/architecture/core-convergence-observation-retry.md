# 受控恢复先前因节点停用而保留的观察

2026-10-23，紧接已完整验收的0f76，同一云端、codex/core-convergence、Draft PR78。本批是P4/P5小阶段，完整保留、容量、伸缩及整体P7仍未完成。

## 实际行为

原队列只读入口现有单条管理员POST `/api/v1/admin/node-observation-intents/:id/retry`。浏览器提交原领取次数的精确十进制字符串和3–400 UTF-8字节原因；服务端复核当前active管理员，锁定具体header、原节点和精确资产状态。只允许held/node_inactive、无活跃token、同一原资产已经启用且凭据未撤销、没有删除墓碑的候选。删除/换资产、无归属位置、材料冲突、有效领取、超过存储次数上限不提供强制覆盖。

同一被检查的领取次数最多排队一次：pending变化与审批审计在一个数据库事务中提交；并发/丢响应后原请求返回409，先读取当前处置后才能明确申请新的候选。该409不声称先前请求未执行，也不会重复重排或新增审批。无全局审计扫描、资金副作用或另一个投影执行器。

排队不读取或修复parts，不改源ID、资产标签、原始位置、counter、Stats/Latest引用或原生配置确认。原执行器仍按原来源哈希、字节上限、顺序、原资产、精确token/lease最终ACK应用；当前节点再次变化仍可能held。接受收据只有accepted和审计ID，不假报观察更新、在线、配置交付或授权续期。

观察执行器另补实际存储计数上限：SQLite为signed integer上限，MySQL为uint64上限；已达上限的待处理/过期领取记录转held/attempt_limit，不回绕到0，不丢材料，同一有界round仍处理下一条。正常领取、租约、2MiB单源/8MiB每轮、32项周期及结算/交付规则不改。

## 前端、权限与事务

现有节点观察队列drawer提供符合元数据条件的“核对重试”，解释接受与应用的区别，必须填写原因并再次点击。当前权限/账户变化清除旧上下文；迟到收据被隔离。响应不明时禁用原候选写入，要求显式刷新；刷新/重新认证/重开没有自动POST。记录读取失败保留原页。原次数和审计ID均不经过Number，超过2^53的字符串不丢精度。

唯一写入在networkstore.ObservationIntentOperations.RetryObservationIntent；复用既有header、审计和worker。HTTP只做认证/严格请求体/能力调用，插件没有新增宿主权限。ownership登记该事务的资源/审计参与者，pending就是已有持久投影意图。

## 兼容、回退及限制

无SQL、字段或新表迁移，154份资产不改。回退应用保留审计、pending、held、所有parts和引用，旧worker按原队列规则处理pending，新的attempt_limit仍为held；先停止新写入并核对有效在途claim，不能为回退清除材料/去重或重置有效租约。本批没有实际清理数据、生产迁移或外部节点操作。

只有可恢复的node_inactive开放重排。其他held原因、applied未引用parts的迟到重放依赖、权威计量保留及整体增长边界仍未解决，不能把此入口当归档完成。fresh worker对象重放测试不是OS崩溃/SIGKILL或真实内核验收。
