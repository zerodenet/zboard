# 本单优惠的实际报价、下单与权益入口

2026-10-23，接在读取兼容基线6bffb693ed6f7549e0e9e0aee2f62e2cdd17d2ed之后，同一codex/core-convergence / Draft PR78。本文只描述本单优惠小闭环；其他P2/P4/P6/P7缺口和原容量门槛继续保留。

## 行为及唯一事务

用户可以在换购、流量重置、流量包结账中显式选择一个已准入原生优惠提供方和可选规则码，核对服务端最终报价，再确认创建订单。普通新购的initial_only/recurring、续费从已付款长期协议继承的规则保持；页面不能替换续费提供方，也不能把首单优惠或长期约定套到其他操作。

本单操作必须收到明确的order_only约定。预检读取归属、可售操作、目标权益及购买快照后结束数据库事务，随后调用现有只读原生报价RPC。最终订单事务重新锁定并核对来源、账户、商品、目标和返回报价；不能把提供方RPC放在资金/权益锁内。提供方停用、配置/运行代次变化、超时、报价失效、需要确认、范围错误或目标变化均返回可解释错误，不会自动以高价创建订单。

订单创建仍走现有OrderCreation唯一写入路径。购买快照保存inner version3及原生宿主确认的提供方、签名、包、代次、配置版本、精确条款和原金额/折扣/最终金额。资金预留、支付事实、实际履约和权益价值继续复用原权威事务；没有第二套扣款或发放入口。已创建订单的相同幂等请求先恢复原订单，不依赖当前提供方可用；已接受快照按原接受时刻验证，不把当前优惠到期错误套到原订单。

换购先对完整新期间基础价打本单折扣，再按原实际已付剩余价值分配抵扣、结余和补差。例如原年付120元/月重置、完整用3个月残值90元，新月付基础20元减2元：新权益价值18元、结余72元入余额。以后目录涨到50元，原新订阅续费基础仍20元；本单2元不自动重复。原实际支付本金与优惠分别保存，不能把优惠变成可退余额。重置或流量包的本单优惠不改变已有续费基础价、期限或原定重置日期。

## 闭环发现的限时流量包估值缺口

首轮原生链路已完成换购、续费、退订、重置及流量包付款，但其后的目标变化探针在报价预检就失败，提供方调用次数为0。第二轮直接读取估值确认，原限时流量包履约生成unsupported_legacy_effect / legacy_value_requires_review。两次真实失败保留，未通过跳过或放宽断言使其通过。

本批补充新履约事实的timed_quota_addition_v1读取/捕获：验证同一套餐、期限、原定重置日期、累计已用和周期基线保持，只有实际新授予额度增加；把增加时已结算的当前残值加本次实际支付金额，在同一原额度周期内按既有RemainingValueBasis和原半入舍入继续计量。后续已付款周期不参与这次重置基数；已消费的原金额不会复活，下一周期不重复折抵流量包。购买基础价/优惠和实付保持不同字段；永久额度仍走原FIFO，不进入该限时模型。

例如年付120元每月重置，当前月原100份已用80份，当前剩余2元、未来11个月110元；当月另付20元获100份，形成当前22元和120份剩余的连续基数。再用100份，当前剩余按既有舍入为3.67元，未来仍110元。再次加购只叠加该时刻残值和真实新付款，不拿目录单价重算旧用量。新事实保留原来源金额，重复/负数/改变期限或未验证、历史unsupported记录均拒绝；不从现价补造旧快照。

真实双库原生链路最终用完同一300元测试余额轨迹后，先结算第一次换购/续费的38元，再新购年付及优惠重置/流量包；剩余实付131元可整份退订，最终余额270元恰等于原300元减已用30元，优惠没有变成新增本金。此算例只有对应冻结时间及实际购买前提成立，不代表任意历史流量包可自动补偿。历史unsupported材料及周期待重置等无法确认的输入继续返回待核对，不伪造零价。

## 发现和前端

发现接口保留legacy operation=new，并追加operations，表示核心允许请求报价的候选操作，不保证插件有优惠或已接受规则。协议范围仍为quote_required。旧服务端没有operations时，前端只保留原新购能力，不能猜测它支持本单写入。

实际账户套餐结账显示本单范围、基础价、优惠、最终价；换购还显示服务端精确残值/抵扣/结余/补差。大额残值字符串用BigInt核对，不经过Number丢精度。编辑规则、切换目标/规格/账户、报价到期或失败清除候选；迟到结果不串目标。提交前持久保存原请求、确认和幂等键；响应丢失/重新加载不自动重放POST，只有显式“恢复上次订单”重用原请求。写操作失败不改选原价。

## 兼容、迁移及回退

无新SQL、表、字段或正式迁移；v3存于已有快照字段。v1首单、v2长期约定的序列化、历史读取、支付及续费规则保持。先前读取兼容提交必须先于本次写入发布。v3订单本身的读取兼容前置为6bff；新增限时流量包估值还必须保留本批timed_quota_addition_v1读取支持。6bff单独会拒绝这种新估值记录，不能作为完整功能回退。应保留新读取器并暂停相关可售操作来调查，停止新写入/在途任务后保留所有订单、接受证据、资金账、权益历史、交付/计量意图；不能通过退回旧估值器强行继续退款。不能退到不识别v3的旧二进制，不能删快照或把v3改成v1/v2来强行履约。生产迁移、发布、真实退款或外部插件修改均未执行。

只读v1原生宿主协议没有有限券的预留/消费/提交/释放。本次不把查询当兑换，也不宣称支付宝/微信/TDCloud或外部券系统已联调。实际优惠插件必须按该范围返回真实报价，不支持的操作可以拒绝；不能为面板要求修改内核或安装Agent。
