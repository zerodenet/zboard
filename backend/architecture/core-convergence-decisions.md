### P3-01：配置交付与原生连接撤权分别确认（2026-10-19）

这是既定授权规则的执行实现，没有新增收费或授权规则。Zero 适配消费固定公开版本 `zerodenet/core@71b3db1` 已有的 `principal_flows`、`active_flows`、`flows.close`，不修改内核、不增加 Agent。实际控制查询及命令是能力证据；版本号、Connector ACK、健康检查仍不能证明配置应用或连接关闭。

`node_config_publishes.phase=connections` 表示精确 SHA 的配置应用已经提交，但旧连接撤权尚需独立核验。该阶段通过已有代次、租约和 worker 恢复；重试只查询原生控制接口并处理连接，不编译/下发配置，也不创建新的发布记录。新业务意图重置阶段并推进代次；旧 worker 不能推进或清除新代次。成功审计与出队同一事务，审计写入失败保留工作。节点删除状态本身不构成连接已关闭的证据。

连接所有权来自持久凭据及订阅，包含退役凭据的节点域摘要；不读取在线统计来推导授权。未知或歧义身份不执行关闭并保留待核验。每次关闭前重新读取、锁定订阅及凭据；SQLite 先取得写入栅栏，MySQL 使用行锁，顺序为订阅后凭据。已恢复的订阅不会使用之前缓存的撤权判断。关闭命令在受限上下文内执行；超时/确认丢失保持未知，下一次重新观察，不盲目重放旧 flow ID。

同一条原生控制连接内校验请求/响应 ID、API ID、core instance 和配置 revision；配置 SHA 使用原有原生配置核验另行确认。原生关闭 ACK 后还须查询确认：仅凭截断分页中找不到某 ID 不能确认关闭。按主体过滤，每页64条，最多8批/512条命令，单次20秒；异步关闭轮询最多1秒，单条授权栅栏最多3秒，响应帧最多2MiB，主体/兼容凭据查找最多4096条。超出边界保留待核验。以上是本批工程上限，不是吞吐承诺。

SSH 使用标准 stream-local forwarding 访问既有 UDS；非 root 账户或禁止转发时可能无法访问。本批不放宽 socket 权限、不安装远端辅助程序、不影响已确认配置或节点接入。管理列表明确显示 `connections_pending`，不把它显示为配置发布失败。完整能力、协议及性能范围以验证记录为准，P3 尚未整体完成。

### D05/D06/D15 细化：交付依据属于冻结的具体绑定

全节点配置SHA证明该次目标，不能使后来新签发的凭据或后来新建的托管前置自动ready。同一编译快照的绑定清单与SHA共同不可变；清单只包含ID和摘要，业务授权、已确认交付及运行观察分别管理。配置确认与绑定投影同事务，恢复只能重建已确认来源，不把当前资源集合补进旧回包。源证据丢失与可重建门槛/投影丢失采用不同恢复边界，后者需核验但不伪造授权或支付事实。详见P3-04及0047升级记录。

### P3-05核实：计量与撤权使用同一规范身份索引

计量的规范归属仍由凭据与订阅决定，不由运行观察或事件指定的订阅ID决定。0046节点摘要投影可以重建，按1024条/节点/次独立推进，未完成不承诺已结算；计量事务不负责吞下整个历史回填。规范源身份更新同事务使派生覆盖失效。完成及累计计量锁顺序收敛为订阅在凭据前，历史撤销身份可归属但不变为可用。此决策没有改变倍率、逐样本取整、配额上限、支付或残值规则。恢复/换购的新权益与旧代次仍未隔离，不以本批索引接入假称已完成。

### P2/P3-06：恢复期间代次、历史计量与凭据

恢复窗口内续费关闭旧额度代次，给新的完整期间签发独立凭据，保留订阅ID/token地址及累计基线；客户端需更新同一订阅地址的内容。普通提前续费沿用当前凭据/用量/重置日。固定公开Zero已核对的认证导出路径未提供可证明的逐流认证时策略代次，因此不将普通ConfigRevision、ACK或心跳当该证据，不改内核/Connector协议或增加Agent。

0048保存旧总额度、关闭时用量、后续迟到计量、方向、期间和触发订单；迟到累计/完成只推进旧额度及游标，不消耗新期间、触发新期间耗尽、重写已结算金额或追缴超用。当前重置查询按代次过滤，收到于新周期的旧记录不混入新周期；同一代次内所有跨周期计量切分仍待P4，不能以此宣称已完成。

既有数据为原始代次0，不伪造过去的支付/代次事实。当前凭据范围1唯一，历史范围NULL并撤销/清密文、保留退休摘要。恢复后同组授权不恢复旧连接。旧式签名user/endpoint报告在多个历史授权订阅或恢复期无法证明归属，返回409并解释使用认证principal事件；原收据幂等及唯一原始期间兼容保留，不猜最新订阅扣量。金融取整、报价时间锁定、基础续费价、实付残值与7天恢复窗口规则不变。

恢复期间并发补记：完成计量与商业事务统一用户SHARE在订阅UPDATE/凭据UPDATE前，避免traffic_records用户外键造成反向等待。派生principal覆盖可以在预备查询后被规范更新失效；完成事务遇到可恢复覆盖错误先回滚，再在同一每请求1024条预算中重新准备，至多3次。真正多归属/损坏不是该重试条件。并发准备、失效、旧身份归属与业务授权仍相互区分，收到/确认必须有已提交事实依据。

### P2-07：完整换购与实付来源守恒（2026-10-20）

按D09执行新换购：报价必须明确确认，旧当前/未来周期按既定实付分摊估值；同一事务把旧残值全额记为消费退款，再用于支付完整新套餐，超额留余额。残值不是商业折扣，新订单实付为完整成交价，原订单实付不重写；管理员改价产生的真实折扣不增加可退价值。当前来源预算、退款、结算、钱包预留/扣款、新期间、关闭代次、凭据换代、审计和发布意图共同提交。

付款前的旧权益抵扣是待结算贡献，不是已经入账或预留的现金。0049保存这部分身份，取消、失败和失效仅释放真正预留的现有余额。新旧来源不能被并发换购/退订重复使用；可信迟到款沿既有可追踪收款入余额路径处理，不能复活已取消权益。等待本身按原QuotedAt锁定时间估值，消费、重置、续费、退款和来源变化仍需重验。

旧已创建、无Version2标记的待付款订单保留原折抵/期限协议；测试通过显式历史行验证兼容，不开放新建旧模式的入口。缺少真实支付或周期快照时返回人工核对状态，不伪造历史实付。新残值总额/分项以十进制整数串传至浏览器，复用钱包BigInt格式化；既有订单单笔价格字段契约保持。换购保留订阅ID/地址，但完整新权益使用新认证凭据及计量代次，旧迟到流量只能消耗关闭额度。

### P2-08：可配置的续费恢复窗口（2026-10-20）

D15现在使用管理员私有配置subscription_renewal_grace_days，默认7个24小时时段；工程边界为整数0–3650天，0表示到期即结束恢复窗口。缩短配置会让超过新期限的旧订阅在清理任务中结束；延长不复活已经ended/canceled的订阅。主动退订仍不进入恢复窗口。列表可售资格、报价、付款履约和凭据清理共用同一业务解析器及持久化策略来源，不按运行观察或投递ACK延长窗口。

配置更新与权威事务通过当前共享读取串行化；付款在等待相关锁后刷新可信时间，重新检查窗口和预留失效。已核验渠道款在权益条件已失效时进入可追踪余额，取消原待付款单，不能复活旧权益。历史非新购订单缺少TargetSubscriptionID时不能猜测同套餐下的另一份独立订阅或制造新订阅；款项同样入余额并要求工单核对。已支付重放保留幂等结果，明确绑定的历史待付款协议继续原有兼容路径。

0050是该策略的唯一初始化入口；通用默认配置协调不得补回已丢失的关键来源。记录0050后丢失配置行/表、元数据损坏或越界值时启动和相应业务失败并要求恢复，不能默认成7天提前清理。迁移中断/重跑保留已有自定义值与revision。到期邮件既有7天历史回看策略独立保留，不冒充续费资格，也未实现余额自动续费。

### P2-09：独立订阅的余额自动续费子闭环（2026-10-20）

D16采用显式用户确认、每订阅独立且默认关闭的授权记录，不从历史订单或管理员分配推断自动扣款许可。授权绑定实际已购币种/周期锁价、当前购买系列及报价权益条件；未购买周期需要先手动确认购买，换购或实质权益变动需重新确认。涨价不改变已购基础续费价。优惠约定缺失时返回可解释暂停，不把未知首次/长期优惠猜成无优惠自动扣款。当前没有优惠插件协议完成的声明。

执行器在数据库内按用户ID、到期时间、订阅ID选择当前到期项，持有同一持久化顺序锁到单份订阅提交；尝试序号与业务提交一起持久化。复用既有余额预留/付款、履约、实付证据、代次与配置交付意图路径，没有新的扣款入账实现或外部渠道调用。余额不足保留账户页面可见状态，5分钟后在恢复窗口内重试；窗口结束、退订或换购，在各自现有事务中停止旧授权。当前不足提醒是账户界面持久状态，尚无本批新增主动邮件/推送，后续需要补齐提醒投递闭环。

实库发现恢复续费也会更新旧订单终态摘要，与自动续费的旧单锁存在等待环。现恢复/手动付款与自动付款、退订统一先锁关联订单再锁用户及相关权益，交易外只读不可变身份、锁内重验目标和快照，保留普通新购的首次读取时机。未用放宽错误检查、扩大超时或无限重试解决死锁。当前继承关联订单1000条上限，超限会暂停该权威动作；自动队列遇该项会返回错误而阻塞本轮后续扫描，是需要收敛的实际可用性限制，不能计为无限历史下可用。

### P2-10：超限项隔离与撤销未来扣款许可（2026-10-20）

历史核对上限与是否仍授权未来扣款是不同职责。只有明确识别的关联订单上限错误，在原财务事务已回滚后，才进入独立的顺序/暂停状态事务；数据库故障、金额归属歧义及其他错误不走这一分支。受影响项本次未扣款，保留可读状态和关闭入口，恢复窗口内每30分钟重验，邻项继续按原有顺序处理。窗口结束仍停止许可。不能将暂停记录当作实付核对、结算或交付成功。

关闭未来扣款许可不需要历史估值或旧订单锁：当前有效用户共享锁、订阅归属读取、许可排他锁及版本检查后关闭并审计，不改变既有订单、余额或订阅。SQLite在同一事务的首次读取前取得对应许可写预留，避免与执行器争用读快照升级。开启许可仍使用既有安全核对及确认规则，超限不因此得到新的自动付款资格。

账户主列表增加一对一许可结果读取及检查时间，提示余额不足/需核对；它是最近一次尝试事实，不是实时余额、业务授权或节点观察。独立订阅各自显示，链接与额度路径保持原职责。没有主动邮件/推送投递的完成声明。
