# Same-account full-page reauthentication: explicit draft recovery

This batch preserves ordinary Plan/SKU and ticket compose/reply drafts across full-page identity login. Inline password reauthentication keeps the existing mounted page. The same shared authentication entry still handles concurrent expired requests, confirms `/auth/me` and refreshes page permission before reading a saved payload. Changing account, losing permission, expiry or invalid material clears the old draft. No payment, refund, replacement, submission or upload is replayed.

Recovery is per tab, account, route and explicit scope, with a ten-minute lifetime, 64 KiB per draft, 192 KiB total and four-entry limit. Only allowlisted form values are captured. Ordinary ticket body text is preserved; attachments must be selected again. Passwords, tokens, private keys, financial facts and accepted quote authorizations are excluded. Storage failure or capacity refusal keeps the original page mounted and explains the refusal. The recovery module never dispatches a business write.

Existing Plan revision and SKU normalized baseline stay attached to the draft. Fresh resource changes make the old draft visible for review but block save, including direct submit-function invocation; the client does not relabel it with a new revision. Closed tickets cannot recover a writable reply. Fresh navigation permission and identity are required even when the stored route appears to match.

Actual targeted result: 81 tests passed in 11.097 seconds; frontend build passed in 29.705 seconds, with unchanged frontend sources. A prior storage-denial test failed because happy-dom caches bound Storage methods on the instance; instance spies now prove both denied writes and authenticated payload reads. The first full original-scope frontend run had 1213 passes, two failures and eight existing skips: the account-subscription fixture routed into the real TicketCenter without Pinia. The fixture now installs real Pinia and supplies its auth-token stub; all original independent subscription/support/no-write assertions remain and pass in the targeted run. The intermediate incomplete-fixture failure and all logs are preserved. Full original-scope rerun is still required; no new exclusions were added.

This is the implemented Plan/SKU/Ticket scope, not every module's OAuth draft completion. Node/group and public settings recovery are separate increments in progress. Mixed sensitive configuration and arbitrary plugin/iframe forms are not scraped or serialized. Browser/real identity-provider acceptance and final-head CI remain unexecuted. No user account or production system was changed.
